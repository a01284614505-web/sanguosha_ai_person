## 1. 目标

**本批不碰任何技能、不加任何锦囊、不动装备。** 只建地基 + 一个验证用例。

## 3. 设计：抽公共机制，并列两条复核线

**不改 `request_response` 的对外契约**（7 个调用点 + `test_response_channel.py` / `test_wuxie_chain.py` 依赖它），而是把底层机制抽出来共用。

```text
                    ┌─────────────────────────────────┐
                    │  _ask_index(player, request,    │  ← 新增：纯机制
                    │             resolver)           │     人/AI/超时/托管/回灌
                    └───────────┬─────────────────────┘
                                │
              ┌─────────────────┴─────────────────┐
              ▼                                   ▼
  request_response(player, req)        request_choice(player, req)   ← 新增
  resolver = _resolve_option           resolver = _resolve_choice    ← 新增
  （现有契约，零改动）                  （四原语共用）
              │                                   │
              ▼                                   ▼
     出闪 / 求桃 / 无懈 / 技能转化      ask_confirm / ask_choose_players
                                       ask_choose_cards / ask_choose_option
```

### 3.1 四个原语的签名

全部挂在 `MainEngine`，`SkillManager` 与 `CardSystem` 经注入的引用调用。

```python
async def ask_confirm(self, player, prompt, *,
                      skill_name=None, context=None,
                      default=False) -> bool
    """是否发动 / 是否执行。返回 True/False。"""

async def ask_choose_players(self, player, prompt, candidates, *,
                             min_n=1, max_n=1, skill_name=None,
                             context=None, cancelable=True) -> List[Player]
    """从 candidates 选 min_n~max_n 名角色。cancelable=True 时允许返回 []。"""

async def ask_choose_cards(self, player, prompt, candidates, *,
                           min_n=1, max_n=1, zone="hand", skill_name=None,
                           context=None, cancelable=True) -> List[Card]
    """从 candidates 选 min_n~max_n 张牌。zone ∈ hand/equip/judge/discard/shown。"""

async def ask_choose_option(self, player, prompt, choices, *,
                            skill_name=None, context=None) -> Any
    """从具名分支里选一个。choices = [{"key":..., "label":..., "detail":...}]。"""
```

### 3.2 复核规则（`_resolve_choice`）

引擎复核是安全边界，**每个原语都必须复核，不能信任前端或 AI 的返回**：

| 原语 | 复核项 |
|---|---|
| `confirm` | 索引 ∈ {0,1} |
| `choose_players` | 数量 ∈ [min_n, max_n]；每个 id 在 candidates 内；对应角色仍存活 |
| `choose_cards` | 数量 ∈ [min_n, max_n]；每张牌仍在声明的 zone 内；owner 仍存活 |
| `choose_option` | 索引合法；key 在 choices 内 |

任一不满足 → 按 `cancelable` 决定：可取消则返回空，不可取消则取**确定性兜底**（候选前 min_n 个）并记 `WARNING`。**绝不允许非法选择落地。**

### 3.3 协议扩展

`require_response` 出站消息**增加一个 `selection` 块**，其余字段不动（向后兼容）：

```jsonc
{
  "type": "require_response",
  "request_id": "resp12",
  "player_id": 0,
  "kind": "choose_cards",              // 新增值：confirm/choose_players/choose_cards/choose_option
  "prompt": "弃牌阶段：请弃置 2 张手牌",
  "timeout": 30,
  "options": [ /* 现有结构不变 */ ],
  "selection": {                        // 新增块
    "mode": "multi",                    // single | multi
    "min": 2, "max": 2,
    "zone": "hand",
    "skill_name": null,
    "cancelable": false
  }
}
```

入站 `player_action` 的 `action` **增加 `option_indices`**，单选继续用 `option_index`：

```jsonc
{"type":"response", "request_id":"resp12", "option_indices":[0,3]}
```

`submit_response(request_id, option_index)` 扩成 `submit_response(request_id, selection)`，接受 `int` 或 `List[int]`，内部统一成列表。**旧签名调用保持可用。**

### 6A-5 弃牌阶段改真人手选 ★ 本批可感知产出

当前 `phase_controller.py:112-121` 按 `KEEP_SCORE` 自动弃。改为：

```python
if player.is_ai or trustee_active:
    discarded = <现有确定性策略>           # 行为不变
else:
    discarded = await ask_choose_cards(
        player, f"弃牌阶段：请弃置 {discard_count} 张手牌",
        candidates=player.hand, min_n=discard_count, max_n=discard_count,
        zone="hand", cancelable=False)      # 不可取消，超时落现有策略
```

超时 / 离席 → 走 `_trustee_choose` → 落回现有确定性策略。**AI 行为逐字节不变。**
