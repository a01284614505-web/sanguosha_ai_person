### 1.4 【重要】发现验收脚本缺陷

`scripts/manual/ws_engine_smoke.py`（R8 用于"严格验收"的脚本）提交场外响应时的 payload 是：

```json
{"type":"player_action","action":{"request_id":"resp9","option_index":0}}
```

**缺 `"type": "response"`**。而 `main_engine.py:438` 的路由是：

```python
if action.get("type") == "response":
    self.submit_response(action.get("request_id"), action.get("option_index"))
    return
```

后果：该脚本发出的每一次响应都进不了 `submit_response`，会等满 `response_timeout`（30s）再落进规则托管。实测一局：

```text
span=562.0s  n=1002
<0.5s        n= 972 sum=   24.1s
0.5-2s       n=   2 sum=    2.2s
2-3s ACK     n=   7 sum=   17.2s
>3s          n=  21 sum=  518.5s      ← 24 次 30s 响应超时
```

**562 秒里 518 秒是超时空转。**

真实前端 `frontend/js/game_main.js:192` 发的是正确的：

```javascript
gameClient.playerAction({type: 'response', request_id: request.request_id, option_index: index}, []);
```

**结论：这不是游戏 bug，是验收工具缺陷。但它意味着"真人回合外响应通道"从未被自动化端到端验证过。** R8 交接里"真实 WS 规则 AI 自驱对局 → winner=lord"的结论本身成立，只是那一局里真人座位其实一次都没真正响应过。

本次新增修正版 `scripts/manual/ws_diag_smoke.py`（带动画 ACK + 消息类型统计 + 无法应答告警），同一路径 17.5 秒跑完。
