## 验收中发现并修正的问题

抽出后对局页停在「等待连接」，360 CDP 看到：

```text
Uncaught SyntaxError: Identifier 'Protocol' has already been declared
    at http://127.0.0.1:8888/js/ws_client.js?v=20260813a:1:1
Uncaught ReferenceError: gameClient is not defined
    at http://127.0.0.1:8888/js/game_main.js?v=20260813a:139:1
```

根因：`protocol.js` 是 `'use strict'; const Protocol = {...}`，经典脚本会把它放进页面共享词法环境；`ws_client.js` 顶部 `var Protocol = require(...)` 即使包在 `if (typeof module !== 'undefined')` 里，`var` 仍会提升并与已声明的 `const Protocol` 冲突，整份 `ws_client.js` 解析失败，`gameClient` 从未创建。原内联脚本与 `ws_client.js` 同页时历史上能工作，是因为旧 `game.html` 自己不声明 `Protocol`，冲突只在拆成外链后暴露。

修复（不属于扩 scope，是让抽出后行为与原内联一致）：

- `ws_client.js` 改为 `globalThis.Protocol = require('./protocol.js')`，禁止 `var Protocol`。
- `window.gameClient = gameClient`、`window.audioManager = audioManager`。
- `game.html` 缓存破坏参数改为 `20260813b`。

未改 `protocol.js`（仍由生成器产出）。`const Protocol` 可在后续脚本里按词法名访问，但不是 `window.Protocol`，`game_main.js` 里已有 `window.Protocol ? ... : Protocol.PROVIDERS` 回退。
