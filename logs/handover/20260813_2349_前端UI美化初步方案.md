## Aim（总目标）

把酒馆前端从「能玩的 CSS 草图」收成一套**官服气质、组件可复用、大厅能秒开、对局看得清也点得准**的 UI。

手段就三件：

1. **令牌 + CSS 组件类**（`.sgs-btn` / `.sgs-panel` / `.sgs-seat` / `.sgs-hp` / `.sgs-card` / `.sgs-modal` / `.sgs-bubble`），大厅到结算共用。
2. **按需搬官服零件**（血条、牌面/牌背、玩家框、背景、木纹），用清单管理，不绑死无名杀整棵树。
3. **大厅减负 + 对局减步**：配置记在本地；出牌接近「点牌 → 点人 → 一点确认」；对手座位能看清血、手牌数、装备。

铁律不变：引擎自驱 / 服务器纯消息泵 / 前端纯 UI。美化不得自造合法操作，不得改协议字段名。

## Objective（可验收）

批准后实施时按这条勾，现在只作对齐用。

1. **设计令牌落地**：色、字号、间距、圆角、阴影、动画时长全部进 CSS 变量（可扩 `frontend/css/main.css` 的 `:root`，或单拆 `frontend/css/tokens.css`）。`game.css` / 大厅 / 结算 / 设置不再散落新的十六进制色。
2. **组件类可点名**：至少有按钮（主/次/危险/禁用）、面板、座位框、血条、手牌、弹窗、聊天气泡。每个类在一份静态示例页 `frontend/ui_kit.html` 上能单独看到默认 / hover / 按下 / 禁用。
3. **大厅一屏能开局**：默认折叠 AI 明细；有本地记忆时，打开大厅即可看到「沿用上次的 4 个 AI」，点一次「开始游戏」能进选将。未记忆或缺 Key 时展开对应卡片，不整页墙。
4. **本地记忆闭环**：刷新大厅后，4 个 AI 的名字 / Provider / URL / Key / 模型 / 温度 / 思考、模式、将池、聊天开关、齿轮设置全部回填。Key **只存在本机** `localStorage`，启动对局时仍走现有 `gameConfig` 通道交给服务器（现状已如此），不新增上传接口。
5. **对局座位可读**：横屏下 4 个对手座位能同时看到立绘、血条图标、手牌数、装备栏摘要；竖屏不叠死、主操作热区 ≥ 44px。
6. **出牌步数**：需要目标的牌 = 点牌 → 点绿色座位 → 点主按钮；不需要目标的牌 = 点牌 → 点主按钮。主按钮在未选目标时禁用。不增加「第四次确认」。协议仍只发引擎给的 `play_card` / `use_skill`。
7. **底部按钮主次**：主操作（出牌/发动）最大；结束出牌次之；技能靠自己头像；「结束游戏」进菜单，不跟主操作抢行。
8. **牌与血用图**：当前引擎会发的标准 + 军争牌，能显示 PNG 牌面；未知牌回退到现有「花色+牌名」卡。血量用官服血条图，不用纯文字「♥♥♥」。
9. **聊天视觉方案完整**：气泡分层（角色台词 / 桌面闲聊 / 系统）、座位上方短气泡、历史抽屉、真人输入条、开关位置全部写清并在 `ui_kit.html` 出静态样例。Stage 8 只接线，不再重新发明样子。
10. **动画可调**：沿用已有 `globalSettings.animation_ms`（默认 1100）。飞牌、选中放大走这一个旋钮。允许以后再加「关动画」而不改布局。
11. **回归不退**：`python -m pytest -v` 维持当前全量（写作时基线 83）；`python scripts/check_frontend_js.py` 过；真实浏览器冒烟路径与 R7 相同（大厅 → 选将 → 对局出牌 → 响应弹窗 → 结束 → 结算）。

## Risk（风险与对策）

| 风险 | 等级 | 对策 |
|---|---|---|
| 和 R8 / 主线 Stage 6–8 抢窗口 | 中 | 本文是独立轨。批准时三选一：先 R8 再 UI、先 UI 再 R8、或 UI 只做 S0 清单不碰页面。未批准不开工。 |
| 无名杀 PNG 版权 / 体积 | 中 | 只拷清单内文件；`noname-main` 继续当素材库不进发布包。计划里写清来源目录。若用户另有自采图，用同一清单覆盖同名文件即可。 |
| 官服框是为无名杀 DOM 切的，硬套会裂 | 高 | S0 先拿 1 个座位做拼装试验（框 + 立绘 + 血条），行了再铺 5 座。失败则框改 CSS 九宫/描边，血条和牌面仍用图。 |
| API Key 进 `localStorage` | 中 | 本机 XSS 能读到。对策：不新增第三方脚本；设置里提供「清除本机记忆」；不把 Key 打进日志 / `console.log`（现状 `lobby.js` 打整份 config，实施时删掉 Key）。 |
| 改出牌流误伤合法操作 | 高 | 只改「点几次、按钮何时亮」，目标集合仍只信 `availableActions.valid_targets`。每步对照现有 `checkNeedTarget` / `selectTarget` / `doPlay`。 |
| `main.css` 再污染对局页 | 中 | 沿用 R7：`game.css` 后挂，`body.game-page` 锁视口。新增组件类用 `.sgs-*`，对局用 `.game-page .sgs-*` 覆盖尺寸。 |
| 横竖屏两套布局做崩手机 | 中 | 先定断点（建议竖屏 `< 700px` 宽走「自己在下、对手横排」；横屏走「自己在下、对手沿上沿」）。S0 用线框，不先写死像素。 |
| 聊天方案写太满，Stage 8 对不上协议 | 中 | 视觉方案只绑定「已有或可预见的字段」（说话人座位、文本、类型）。未知字段画占位，不发明引擎事件。 |
| 范围蔓延到锦囊补全 / 皮肤本体 / 真聊天 | 高 | 明确不做见下。碰到就停、请示。 |
| 动画「留修改空间」变成无标准 | 低 | 只暴露已有 `animation_ms` + 一个 `animation_level: off \| medium`（默认 medium）。不加粒子系统。 |

三条铁规则（5 分钟离席只结束对局、无懈链无深度上限、AI 整局会话 + L0 无玩家内容）本次零改动。

### 明确不做

- 不改引擎规则、不改 WS 协议字段名、不改服务器消息泵。
- 不上 React / Vue / Web Components。
- 不把 `noname-main` 整棵打进前端或 APK。
- 不实现聊天收发（Stage 8）。
- 不补 Stage 6 剩余锦囊、不做 Stage 7 皮肤本体（多皮肤切换可在令牌里留口）。
- 不记「上次选的武将」。
- 不把响应弹窗交互作为本轨主目标。

## Stages（全部阶段，批准后才执行）

### S0 盘点与线框（不改线上观感）

- 对照引擎牌 id，列出 P0 牌面缺哪些 PNG。
- 用 1 个座位把「金框 + 现有武将 jpg + official 血条」拼一张静态 HTML，确认切图能套。
- 画大厅 / 对局横屏 / 对局竖屏三张线框（可就写在本文后续修订，或单独一页）。
- 写出 `MANIFEST.md` 草稿（尚未拷文件）。
- **出口**：座位拼装能看；牌面差集表；线框得到你点头。

### S1 令牌 + 组件橱窗

- 落地 `tokens.css` + `components.css` + `ui_kit.html`。
- 组件只服务视觉，不接 WS。
- 聊天气泡三种类型先画在橱窗里。
- **出口**：橱窗在手机横竖屏都能点过一遍，无横向撑破。

### S2 拷 P0 资源

- 按清单拷进 `frontend/assets/ui/`，写死 MANIFEST。
- 不改页面引用之外的逻辑。
- **出口**：目录体积可接受（目标：P0 合计远小于整棵 `noname-main/image`）；缺图表归零或标明「回退 CSS」。

### S3 大厅简洁 + 本机记忆

信息架构（草案）：

```
[酒馆标题]                          [⚙]
[开始游戏]          ← 有记忆时这是主路径
[座上宾 4/4 ▾]      ← 默认收起；展开为 4 张卡片
[更多 ▾]            ← 将池 / 聊天开关 / 身份卡
[连胜 n · 总对局 m]
```

- 4 个 AI 默认折叠成一行摘要（名 + 模型）；点开才见 Key / URL / 温度。
- 「同步给其他 AI」保留，放在展开态。
- 新键 `localStorage.lobbyMemory`（或拆 `aiProfiles` + 沿用 `globalSettings`）。`gameConfig` 仍只在点开始时写，给选将/对局用，避免和长期记忆搅在一起。
- 设置里加「清除本机 AI 与大厅记忆」（不清胜场）。
- 删掉 `startGame` 里把整份 config（含 Key）打到 console 的日志。
- **出口**：刷新回填；无记忆时展开空卡；有记忆时一键开局。

### S4 对局桌面（视觉 + 交互）

座位：

- 对手不再是 72px 小卡片。横屏沿上沿（可微弧）；竖屏仍在上但加宽信息条（血图标 + 手牌数 + 装备点）。
- 自己区：左侧座位（框+血+装备），右侧手牌，底栏只留主/次按钮。

出牌流（相对现状）：

- 现状：点牌 →（若要目标）点绿座 → 点「出牌」。保留这三步，但：
  - 选中牌立刻抬起并显示官服牌面；
  - 主按钮文案在「出牌 / 发动」间切换，未选目标时禁用（现状已有，保持）；
  - 「结束游戏」离开底栏；
  - 技能入口挪到自己头像旁，避免四键并列。
- **暂不做**「点目标自动出牌」（留作后续开关，避免和场外响应抢手）。

牌：手牌 / 弃牌顶 / 飞牌用 P0 PNG；没有图的 id 回退旧卡面。

血：`official` 图按当前血/上限拼接，护甲用 `shield`。

**出口**：R7 冒烟路径可走完；横竖屏都能出一张杀。

### S5 选将 / 结算 / 设置换皮

- 换 `.sgs-*`，接同一背景与按钮。
- 选将网格用武将图 + 官服卡框，不改选将协议。
- 结算身份揭示用座位框小卡。
- **出口**：三页不再像三套皮肤。

### S6 聊天视觉定稿（仍不接线）

写进橱窗 + 对局占位：

| 元素 | 规格草案 |
|---|---|
| 座位短气泡 | 出现在该座位上方，最多 2 行，约 2.5s 后淡出（时长跟 `animation_ms`） |
| 类型色 | 角色台词 / 桌面闲聊 / 系统 三套 `.sgs-bubble--voice \| --table \| --sys` |
| 历史抽屉 | 从右侧或底部拉出，按时间，带座位色点 |
| 输入条 | 仅真人生效；占底栏上方一条，不挡手牌 |
| 开关 | 大厅「更多」里已有「启用 AI 聊天」；对局里在菜单再放一个静音气泡 |

Stage 8 只把真实消息填进这些槽。本阶段 DOM 可以先挂空节点，也可以只在橱窗展示——S0 线框时二选一，默认**对局挂空节点**以免 Stage 8 再拆布局。

**出口**：橱窗三种气泡 + 对局空壳位置你点头。

### S7 横竖屏收口

- 断点与安全区（刘海 / 虚拟键）走 CSS。
- Termux 内置浏览器目标：先 Chrome/系统 WebView 尺寸，不特化某机。
- **出口**：同一套页面 360×800 竖屏、800×360 横屏都不挡主按钮。

### S8 动画层

- 飞牌、选中放大、阶段切换用中度动画。
- 单一旋钮：`animation_ms` + `animation_level`。
- **出口**：调到 0 / off 时布局仍完整，只是瞬间到位。

## 和现有代码的对齐（写计划时的实况）

- 大厅 `index.html` 把模式、名字、4 个 AI 全量表单、将池、聊天、开始键堆在一页。`lobby.js` 的 `loadUserData` **只回填胜场**，不回填 AI / 模式。`startGame` 把含 Key 的 config 写入 `gameConfig` 并 `console.log`。
- 对局手牌是 CSS 画的花色+中文名，没用 `frontend/assets/cards/*.png`。对手框 72×、头像 48×，信息挤。底栏四键：出牌 / 技能 / 结束阶段 / 结束游戏。
- `globalSettings`、音量、牌堆、胜场已经在用 `localStorage`，本轨是补「大厅长期记忆」并禁止把 Key 打进日志。
- R7 已把 `game.html` 拆成结构 + `game.css` + `game_main.js`。本轨在这个结构上长，不重新单体化。
