## 做了什么

1. **引擎累计**：新增 `game_engine/token_usage.py`（桶结构、累加规则，单一真相源）。`MainEngine` 增 `usage_stats` 与 `record_usage(player_id, kind, usage, failed)`。
2. **出牌/响应/选择**：`AIDecision._call_with_session` 在调用成功后按其 `kind`（取值即 `decision` / `response` / `choice`，无需映射）累计；网关抛异常时计 `failures`。
3. **聊天**：`ChatEngine` 改用 `gateway.call_ai(..., return_usage=True)`，返回文本与错误处理保持不变；成功计 `chat`，三类异常分支计 `failures`。`ChatEngine` 构造新增可选参数 `usage_sink`，由 `MainEngine` 传入 `record_usage`。
4. **累计规则**：
   - `calls` 每次调用必加。
   - `failed=True` 时计 `failures`，不计入 `unknown_usage_calls`（失败没有响应，谈不上缺用量）。
   - `prompt_tokens` 或 `completion_tokens` 缺失（或非数字）时计 `unknown_usage_calls` +1，已有字段照加，缺失字段不当 0。
   - `cached_tokens` 为空时不累计、不计入 unknown（很多服务商本就不报告该字段）。
5. **局后日志**：`game_logs.build_game_log` 增 `token_usage`，列表，每个 AI 座位一行：`id`、`name`、`provider`、`model`，`kinds` 含四类调用的完整桶（无数据时为零）。不含 Key 与地址。
6. **日志页**：`frontend/js/logs_page.js` 在"角色"表后渲染"Token 消耗"表（行=AI，列=决策/响应/选择/聊天，单元格为次数、入/出 token，并标注失败与缺用量）。没有任何调用数据时整张表不显示。
7. **测试**：新增 `tests/test_token_usage.py`（12 项）。
   - 累计：`test_usage_accumulates_per_seat_and_kind`
   - 未知 kind 拒绝：`test_unknown_kind_is_rejected`
   - 缺字段计未知：`test_missing_fields_count_as_unknown_not_zero`、`test_non_numeric_usage_values_are_treated_as_missing`
   - 失败计数：`test_failed_call_counts_calls_and_failures_but_not_unknown`、`test_gateway_exception_on_decision_path_is_counted_as_failure`
   - 决策路径按 kind 累计：`test_successful_decision_call_is_counted_with_its_kind`
   - 聊天被统计：`test_chat_call_is_counted_as_chat`、`test_chat_failure_is_counted_and_does_not_break_the_call`、`test_chat_without_usage_is_counted_as_unknown`
   - 局后日志：`test_game_log_carries_token_usage_per_ai_without_the_key`（断言整个日志 JSON 不含测试 Key 与中转地址）、`test_game_log_token_usage_is_empty_zeroes_when_nothing_was_called`

## 待确认 / 遗留

1. **预存的小问题（未改）**：`AIGateway.extract_usage` 用 `usage.get("prompt_tokens") or usage.get("input_tokens")`，服务商若真实返回 `prompt_tokens = 0`，会被 `or` 短路成 `None`，于是计入 `unknown_usage_calls`，而不是 0。这在 0 token 调用上极少见，但属于计数口径问题；如要修，应改为显式判断 `None`。本批没有改 `extract_usage`，因为它不在规格内。
2. 真 Key 实测由用户完成：局后打开日志页，确认表格出现且数字合理；日志 JSON 中 `token_usage` 应为每个 AI 一行。
