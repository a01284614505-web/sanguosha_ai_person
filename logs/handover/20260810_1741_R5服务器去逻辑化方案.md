## Context
R0–R4 已完成，`game_server.py` 仍直接承担配置规则校验、武将加载与分配、牌堆管理、结算事件合成、动画等待判定和统计魔法数字，违反“引擎自驱 / 服务器纯消息泵 / 前端纯 UI”铁律。R5 是本轮最高风险阶段：既要把游戏域职责归还引擎，又必须保持现有协议、动画节奏和三条用户规则不变。
## Aim
把 `game_server.py` 收敛为 HTTP/WebSocket 传输适配层，使配置、武将、牌堆、结算及统计只由 `game_engine` 门面决定；最终服务器文件不超过 300 行，71 项既有测试和完整运行链路保持通过。
## Objective
1. `game_server.py` ≤ 300 行，且无武将分配、模式/人数/牌堆规则校验、游戏事件合成、统计魔法数字及 `deck_manager` 直接导入。
2. 服务器业务入口只调用 `MainEngine` 门面；JSON/HTTP/WS 解析、连接映射、动画 Future 与 2.5 秒超时仍留在服务器。
3. `data/heroes.json` 成为武将运行数据的单一加载入口；开局规范化与 AI 世界书复用同一注册表数据。
4. 玩家主动结束时由引擎唯一发出最终 `state_changed` 与 `game_end`，保持 `end_game_accepted` 回执，且结算只发送一次。
5. 动画是否等待 UI 由引擎通过 `await_ui=True` 声明；服务器只执行 ACK/Future/2.5 秒超时。
6. 牌堆列表、切换、配置校验均经引擎门面；现有 REST 响应字段和状态码保持不变。
7. `server_info` 的武将/技能统计来自注册表和 `SkillManager.registration_stats()`，不再写死 27/54/54。
8. 不改 71 项测试断言、协议字段及三条铁规则。
## Risk
| 风险 | 等级 | 对策 |
|---|---|---|
| 主动结束漏发或重复结算 | 高 | 引擎建立幂等终局发送；专项 WS 冒烟核对回执及单次 `game_end` |
| 主动结束被真人等待或 AI 调用拖住 | 高 | 立即置终局、唤醒真人等待并由引擎发送终局；循环收尾不重复发送 |
| 武将双数据源合并引起缓存前缀漂移 | 高 | `data/heroes.json` 为唯一源；只替换加载入口，不改 L0/L1/L2 构造顺序 |
| 配置迁移改变兼容字段或默认值 | 高 | 原样迁移并每小步跑 71 项回归 |
| 牌堆 REST 契约漂移 | 高 | 门面内部复用 `DeckManager`，保留状态码与 JSON 字段，跑真 HTTP 测试 |
| 动画节奏变化 | 中 | 只搬 `await_ui` 声明权，Future、ACK 和 2.5 秒超时原样保留 |
| 为达到行数目标牺牲可读性 | 中 | 抽取职责与复用纯转发工厂，不用压缩式语句凑行数 |
