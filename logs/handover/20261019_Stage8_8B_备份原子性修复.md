# Stage 8B 导入与包管理专项交接

日期：2026-10-19  
范围：武将包持久化边界、当前注册表读取校验及注册表接线；未修改 DSL、运行时或 ROADMAP。

## 修复

`hero_package_store._atomic_write()` 之前直接把当前注册表字节写到最终备份文件名。若写入中途失败，备份目录可能留下一个符合命名规则、但内容不完整的文件，管理页会把它列为可恢复备份。

现在先在 `backups/` 内写临时文件并 `flush`、`fsync`，再用 `os.replace()` 原子发布备份；提交当前注册表前尝试同步备份目录。备份写入或替换失败时会清理临时文件，当前注册表继续保持原字节。主注册表仍通过同目录临时文件原子替换。目录 `fsync` 是跨平台 best-effort；其 `OSError` 会被忽略，因此不构成所有存储故障下的断电持久性保证。

专项测试注入备份临时文件的 `fsync` 失败，验证现有注册表字节及启用将池不变、已存在备份仍可读取、失败临时文件被清理。

当前包文件此前只校验顶层字段。现在 `list_packages()`、`enabled_heroes()`、`import_hero()` 和 `set_enabled()` 共用 `_read_current()`，复用文档校验并将其规范化结果交给消费者；读取不会写磁盘，现有 Store 生成的合法 schema 不变。损坏的本地存储转换为 `RuntimeError`，不会被导入 API 当作用户输入错误返回 400。导入在写入前也验证最终文档，并在包数达到 500 时拒绝新增包，避免写出下一次自身读取会拒绝的注册表。

`HeroRegistry` 改为调用 `HeroPackageStore.enabled_heroes()`。启用包中有损坏内层记录时注册表加载失败，不会把不可信记录带入将池。`restore_backup()` 仍独立校验备份并可覆盖损坏的当前注册表，保留故障恢复路径。

新增故障注入覆盖主注册表 `os.replace()` 失败：已发布备份保持有效、当前文件不变，临时文件清理。另验证内层损坏会阻止启用和导入写回、HTTP 将损坏当前存储返回为 500、注册表拒绝损坏启用包、恢复备份可修复损坏文件、包数上限不会被写穿。
