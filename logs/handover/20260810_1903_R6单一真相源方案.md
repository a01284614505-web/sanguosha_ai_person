# R6：协议、Provider、牌表与序列化单一真相源 — 实施计划

## Context
R5 已完成（提交 `94f05fe` / `6ea990f`），`game_server.py` 收敛为 255 行纯消息泵。C 档重构总计划 `C:\Users\Administrator\.claude\plans\tranquil-forging-rivest.md` 的 R6 章节（8-07 起草）定义了本阶段：协议 + provider + 牌表 + 序列化各自收敛为单一真相源。总计划的行号引用已随 R2–R5 大量漂移，本方案重新定位全部改造点，并在小处落实总计划的取舍。三条用户铁规则（5 分钟离席只结束对局不结束服务器、无懈链无深度上限、AI 整局会话复用 + L0 无玩家内容）均不受影响。

## Aim（总目标）
协议消息类型、Provider 清单、牌名属性和卡牌序列化各自只剩一处定义；服务器、前端、引擎全部改读该处，消除手写分散副本与历史漂移，为 R7/R8 铺路。

## Objective（可验收目标）
1. O10：协议消息类型与 provider 清单各只有一处定义。`game_engine/protocol.py` 是 Python 侧唯一来源，`scripts/gen_protocol_js.py` 生成 `frontend/js/protocol.js` 供前端引用，且有一项单测断言二者同步；前端 3 处 provider 硬编码（lobby.js / game.html / global_settings.js）删除，改读服务端下发。
2. O11：运行时牌名/牌属性硬编码从 8 处收敛到 1 处 `game_engine/card_table.py` 的 `CARD_TABLE`。8 处消费点逐一改为查表：wuxieable 集合、use_card 分发链、rules_engine 校验链、main_engine 合法操作生成、phase_controller 弃牌启发式、ai_decision 出牌优先级、deck_manager 图片名映射、extract_noname_deck 名称映射。
3. 序列化去重：卡牌 dict 构造收敛为 `state_manager.card_to_dict()` 单点；删除无调用点的 `state_manager.to_dict()`；合并 `_notify_card_ui`/`_present_used_card` 与 `use_bingliang`/`use_lebu` 两组重复函数。
4. 全部既有 71 项测试保持通过；新增协议同步断言（总计划批准的例外）；牌表一致性断言并入既有 `tests/test_real_decks.py`（不新增文件）。
5. 规则 AI 自动对局跑完一整局；`scripts/check_frontend_js.py` 通过；HTTP/WS 冒烟通过；`git diff --check` 通过。
6. 服务器 `server_info` 携带 providers 清单；新增 REST `GET /api/providers` 供无 WS 页面（lobby/设置页）拉取。
7. 不改变任何协议字段名、不改 71 项既有断言、不改三条铁规则、不改 5 分钟看门狗/无懈终止/AI 缓存分层行为。

## Risk（风险与对策）
| 风险 | 等级 | 对策 |
|---|---|---|
| 牌表改造破坏结算链（最高风险：8 处消费点全依赖牌名逻辑） | 高 | 每改一处跑一次完整回归；先建表 + 一致性断言，再逐处替换，不批量改；规则 AI 整局对局验证引擎自驱 |
| 牌表与牌堆数据漂移（手写表 vs data/*.json） | 高 | 一致性断言：表键集 == 标准∪军争牌名集；每张牌的 card_type/target_rule 与牌堆 JSON 逐项比对 |
| 协议常量改造漏改前端发送/接收点 | 中 | protocol.js 生成 + 同步单测；check_frontend_js.py；WS 端到端冒烟核对全部 8 入站 14 出站 |
| provider 下发改动前端渲染时序（lobby/game/设置页异步 fetch） | 中 | 各页保留默认回退（fetch 失败用内置深拷贝回退值）；冒烟逐页人工核对下拉框 |
| 序列化统一改变手牌/操作候选字段 | 高 | card_to_dict 生成的字段名与现值完全一致（id/name/suit/rank/card_type；手牌另加 index/target_rule）；不改 `type` 之外的任何字段 |
| extract 工具改造破坏一次性提取流程 | 低 | NAME_MAP 改为从 CARD_TABLE.source_key 派生，跑一次 dry-run 验证产物一致 |
| 测试数量偏离 71 基线 | 低 | 方案中明示：+协议同步测试（总计划批准例外，新文件 test_protocol_sync.py）；牌表一致性断言并入 test_real_decks.py 不新增文件 |
| onEndGameAccepted 补回调改变主动结束交互 | 低 | 只加轻量回执提示，不动 end_game → game_end 主流程 |
