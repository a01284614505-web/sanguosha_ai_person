5. 结论
   - 画廊：27 将网格 + 搜索 + 势力筛选；点武将开面板（默认原画、已导入、候选、最后一格“＋自定义导入”）；“使用中”徽标 + 金边；恢复默认；无英文 ID 输入框、无红字。通过。
   - 服务器存储：通过。**选择：统一资源目录 + 档案级选择表。** `SANGUOSHA_SKIN_DIR`（默认 `data/skins/`，已 gitignore）下：`profiles/<profile_id>/skins.json`（hero_id→skin_id 选择表 + 导入元数据）、`profiles/<profile_id>/uploads/<up_32位hex>.<png|jpg|webp>`（按档案隔离的导入图）、`noname/<hero_id>/<n>.jpg`（所有档案共用一份候选缓存，307 张共约 45 MB，不按档案复制）。浏览器只认 `hero_id + skin_id`（`up_…` 导入图，`nn_<n>` 候选）。
   - 接口：`GET /api/skins?profile_id=`、`GET /api/skins/catalog`、`GET /api/skins/image?hero_id&skin_id[&profile_id]`、`POST /api/skins/upload?profile_id&hero_id&label&client_ref&select`（原始图片字节）、`POST /api/skins/select`、`POST /api/skins/delete`。
   - 安全：profile_id 用 `validate_profile_id`；hero_id 必须在 `HeroRegistry` 武将表（含已启用武将包）；skin_id 只接受 `up_[0-9a-f]{32}` / `nn_\d{1,4}`；路径只由校验过的 ID + 固定扩展名拼出，不使用任何用户文件名；上传 ≤2 MiB（Content-Length 先检查，超限不读入，≤8 MiB 的超限体读掉丢弃以便返回 413）、Content-Type 必须与魔数一致、自己解析 PNG/JPEG/WebP 头校验 64–2048 像素；每档案最多 40 张/40 MiB；写接口要求自定义头 `X-SGS-Skin: 1`（服务器不响应 OPTIONS，跨站网页无法直接 POST）；图片响应 `nosniff` + 固定 Content-Type。测试覆盖：`../`、斜杠、%2F、空、超长 ID，未知武将，MIME 与魔数不符，SVG/GIF/文本伪装，过小/过大尺寸，超 2 MiB（413），缺标记头（403），跨档案读/选/删，候选路径注入。
   - 候选代下载：通过（用打桩的 fetcher 测试）。首次请求才从固定提交的 raw.githubusercontent.com 拉取，核对字节数与 git blob SHA-1 后原子落盘并缓存；并发请求同一张只拉一次；失败返回 502 + 明确提示（含脚本名），30 秒内不重复打 GitHub；选用时先确保缓存成功，失败则不会标“使用中”。画廊里失败的缩略图显示“拉取失败 点此重试”并在面板状态行写明原因。备用脚本 `scripts/download_noname_skins.py`（可 `--hero`、`--dir`，可重复运行补齐，每张三次重试）。
   - **未检测：真实 GitHub 下载。** 本沙箱代理拒绝 `raw.githubusercontent.com`（403 CONNECT），所以 `default_fetcher` 与脚本对真实网络的行为没有实测；浏览器截图用的是把本地武将立绘调色后灌进缓存的“假候选图”。请 Opus 或用户在能上外网的机器上跑一次脚本确认 307 张哈希都对得上（目录里的 sha1/bytes 来自固定提交，理论上应一致）。
   - 迁移：通过（真实浏览器验证）。皮肤页和大厅空闲时检查旧 IndexedDB `sgs_local_skins_v1`：对每条“武将→本地皮肤”绑定上传到服务器（`client_ref` 去重、`select=if_empty` 不覆盖已有选择），服务器全部 200 才写 `localStorage.skinMigrated`；有网络/5xx 失败则不标记，下次打开自动重试，皮肤页有“重试迁移”按钮；4xx（格式/尺寸不合规）计为被拒收并提示。**永不自动删除旧数据**，迁移完成后在“在其他设备使用同一套皮肤”折叠区提供用户手动点的“清理旧副本”。局限：未绑定任何武将的本地图片无法归属武将，不迁移（提示数量，仍留在浏览器里）。
   - 不闪烁：通过。`sgs_common.js` 把“hero_id→皮肤地址”表缓存在 localStorage（`skinMap`，带档案 ID），脚本一加载就同步读取，`heroImageURL/heroImgHTML` 首次渲染就用皮肤地址；页面启动后再向 `/api/skins` 取一次，只有表变化才改已画出的头像。验证：用 MutationObserver 记录每个头像 `src` 的全部历史，选将页、图鉴页、对局页（359/412/432/1440 四个视口各开一局）中被换皮武将的 src 历史长度恒为 1 且为皮肤地址。已知局限：一台设备**第一次**用某档案、且没有先打开过皮肤页时本地没有缓存，首屏会先用默认图，表到达后再换一次；通过“切换档案”按钮会立刻写入缓存。
   - 跨浏览器上下文同档案：通过。电脑上下文导入/选用后，另开全新浏览器上下文（手机触摸仿真）只设置同一 profileId，皮肤页与 skinMap 即看到同一套皮肤。
   - 新增了一块 UI 需要说明：档案原本只存在各浏览器的 localStorage，没有“换设备用同一档案”的入口，所以皮肤页底部加了折叠区“在其他设备使用同一套皮肤”（显示/复制档案 ID，输入另一个档案 ID 并二次确认后切换；提示切换会连战绩、AI 档案一起切换）。这是对“电脑和手机用同一档案”最小可用的实现，是否保留请 Opus 决定。
