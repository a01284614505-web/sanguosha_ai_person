# P5 AI 档案与称号交接

## 交付范围

P5 增加四个固定 AI 选手账号（`ai_1`–`ai_4`），按浏览器 `profile_id` 分档保存。大厅可给选手改名、选择上场选手；选中已在另一席的档案时自动与两席互换。提供方、模型和 API Key 随选手档案配置，Key 仍只在浏览器存储。服务端开局时以档案中的 AI ID、名称和佩戴称号为准，客户端不能改写身份。换名或换模型不重置该选手战绩。

称号规则位于 `data/ai_titles.json`，人类与 AI 共用统计和解锁函数。作弊局正常保留对局历史，但不更新人类或 AI 的称号统计、AI 档案历史和奖励。服务端以 game_id 幂等结算；重复 GAME_END 返回同一回执，不重复增加统计。历史页支持查看四位 AI 的简要历史、改名和佩戴已解锁称号；人类可单独选择称号。下拉提供“自动最高”与“不佩戴”两种空称号状态。首轮阵亡取引擎实际死亡轮次，不依赖终局轮数。桌面牌桌、结算页和大厅显示佩戴称号；高级/稀有称号有 CSS 动效，`prefers-reduced-motion` 下静态呈现。

## 保守授予边界

- “深藏不露”只统计获胜的忠臣、反贼或内奸，主公因身份始终公开而排除。必须有每个其他笔记所有者在其存活期间、每个尚未公开轮次对目标做出的本轮有效判断；快照的 `judged_seats` 用来区分本轮新判断和沿用旧笔记。任何模型在身份公开前以高把握猜中真实身份即不授予。按 P0 `game_state._public_seats` 映射快照的公开座次键；缺所有者快照、缺轮次或无实际判断均不给奖，避免缺笔记模型因少留下猜中记录而受益。服务器结算只消费引擎临时生成的候选 ID，字段在持久化日志和前端消息前删除。
- “渔翁得利”仅在主循环行动边界实际观察到存活者恰为主公与内奸，且之后主公阵亡、内奸成为唯一存活者时授予。一次群体结算从三名以上存活者直接造成该结果，不会因阵亡回调顺序而被误认为单挑；最终剩余角色也不能反推此前发生过单挑。
- 现有旧档可继续读取，但 P5 统计从上线后的可识别固定 AI ID 开始；旧 AI 日志没有稳定 AI 账号 ID，未做猜测式回填。人类称号统计也从 P5 上线后开始，避免把缺字段的旧局误记成零或错算身份。
- 侦探称号依方案暂缓；尚无可靠准确率统计口径。

## 集成与审查修正

已经把 P5 的两个独立提交重放到 P4 之上，`feat/ai-smart-p5` 包含 P0–P5 全部改动。冲突合并保留 P0 统一 seats 映射、P3 的 plan 快照、P1 的 CHAT_REJECTED 双重隐私闸门。

- 序列化玩家顶层带固定 ai_id，结算按档案而非桌位归属，避免互换座位后战绩串档。对局期间在档案页改名，旧对局结束也不能覆盖新名字。
- 保留每次高把握判断的事件记录，哪怕 AI 本轮后来改口，仍然不能获取“深藏不露”；不能只看轮末快照。
- 档案下拉保留“自动最高”与明确选择的差别，不因保存名字而把自动模式固定为当时称号。结算页以最新结算回执显示佩戴称号与新获得提示。
- 旧本地配置迁移要等服务器写入成功才标记完成；失败不假报完成、下次可重试，开局也等迁移/改名完成。
- 称号在昵称上方独立一行牌匾，手机四字完整，不挤掉座位号。减少动态效果使用足够的 CSS 优先级停止流光。
- 补查延时锦囊的无懈提示：原始锦囊来源取 trick_user，不把被判定者误说成锦囊使用者；未知时明确写未记录。普通自用锦囊按牌表提示自身目标。仅改提示与上下文，无懈链深度、次序及真实消耗未改。
