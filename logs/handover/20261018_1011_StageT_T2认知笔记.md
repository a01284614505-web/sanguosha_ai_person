## 6. 后续预期与遗留事项

### 实现上的裁定（方案没写清，需要知道）

1. **座位号约定**：存储键 = 座位 id（0 起），对模型和前端显示 = id + 1（与账本汇总、席间发言的"N号"一致）。出站 `cognitive_notes` 里每行同时给 `target_id` 和 `seat`。
2. **"不进会话消息"的读法**：笔记存在 `engine.notes` 独立结构里，不是会话窗口的一部分；每次出牌决策把当前笔记重新注入 L2。但 L2 本身仍像账本、发言区块一样被追加进会话窗口，所以**旧版本笔记文本会留在窗口里的旧 L2 中**，并随压缩被并进"前情概要"（概要只取每条 L2 的前 80 字，落不到笔记区块）。要做到"旧 L2 里的笔记也剔除"就得改写已入窗口的消息，会破坏前缀缓存，所以没做。见"待确认"1。
3. **`why` 超过 20 字截断到 20 字保留**（调度裁定 2026-10-18，原实现为整条丢弃）；非字符串仍整条丢弃。
4. **必须三个字段齐全**才算合法条目（`why` 可以是空字符串）。
5. **重大事件 = 有人阵亡**。引擎里身份揭示只发生在阵亡（主公开局即公开，不算事件），阵亡暗置时阵亡虽不揭示身份，仍视为重大事件提示复核。
6. **下发时机**：作弊局里，AI 出牌决策返回后若笔记有变化就整表下发（所有 AI 的笔记 + 各自 `last_reasoning` 的最新公开理由）。所以：(a) 阵亡所有者的 `frozen` 标记要等到下一次别的 AI 笔记变化时才会刷新到前端；(b) "最新理由"可能来自响应/选择决策（`last_reasoning` 每次决策都会覆盖），与 `decision_trace` 里的理由同源，都是模型主动给出的公开理由，不含隐藏思维链。
7. **笔记所有者登记**：`run()` 启动时登记有 Key 的 AI；中途给无 Key 座位填 Key 时，首次出牌决策的 prompt 构造会登记。所有者一旦登记，之后即使把 Key 清掉也仍在快照里（只是不再更新）。
8. 作弊局重连补发的是"当前最新全表"，不是历史。
9. 非作弊局：引擎不构造（`cheat_notes_payload()` 为 `None`），服务器第二道闸门再丢一次；前端 `G.notes` 在非作弊局恒为空。
