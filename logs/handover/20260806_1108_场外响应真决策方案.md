## 1. Aim（总目标）

让「被杀时出不出闪、濒死时救不救、要不要无懈」这类**回合外决策**，真正由**真人自己点**和**AI 真调 API 想**，而不是代码替他们抓手牌里的第一张。

引擎依旧是唯一真理来源：**引擎算出合法候选 → 人或 AI 只能从候选里挑 → 引擎复核后才执行**。谁都不能绕过规则，包括 AI。

## 7. 上下文缓存策略（你委托我定，本节即最终方案）

目标：同一 AI 玩家整局命中自己的前缀；多个 AI 玩家用同一模型时，**连彼此之间也能命中**。

### 7.1 三层前缀分层

消息列表严格按 L0 → L1 → L2 排列，**越稳定的越靠前**（各家前缀缓存都是从头逐 token 匹配，一处变动后面全废）：

| 层 | 内容 | 变化频率 | 共享范围 |
|---|---|---|---|
| **L0 全局层**（system #1） | 三国杀通用规则摘要、卡牌效果表、输出 JSON 格式规范、「引擎是唯一真理来源，只能从候选里挑」的硬约束 | **整局不变，且与玩家无关** | **同 provider+model 的所有 AI 玩家逐字共享** |
| **L1 角色层**（system #2） | 你的武将人设世界书、技能说明、你的身份、开局座次表 | 整局不变 | 单个玩家 |
| **L2 局势层**（user，追加） | 轮次、各家体力、你的手牌、当前请求（出牌/响应/濒死）、**引擎给的合法候选列表** | 每次都变 | 单个玩家，只追加在末尾 |

关键约束：**L0 的构造函数不接收 player 参数**，从物理上杜绝把玩家名/身份/手牌写进 L0（R14）。这是「跨玩家命中」能否成立的唯一前提。

现状问题：`WorldbookManager.build_full_worldbook(player, game_state, available_actions)` 把人设和手牌**揉在一个字符串里每次重算**，前缀每次都不同 —— 等于现在的缓存命中率接近 0。所以 S4 必须先把它拆成 `build_static_worldbook` / `build_situation`。

### 7.2 会话窗口

`AIDecision._sessions: Dict[player_id, List[dict]]`，每个 AI 玩家整局一个窗口，**只追加不重排**：

- 开局构造一次 L0 + L1，之后再也不动
- 每次决策：append 一条 L2 user 消息 → 调 API → append 模型返回的 assistant 消息 → append 一条极短的「引擎实际执行结果」user 消息
- **出牌决策、响应决策、聊天全部共用同一个窗口**。这既是省钱，也是让 AI 记得住自己刚才干了什么（符合你要的「像真人」）

### 7.3 压缩而不是滑窗

窗口超过阈值（默认 24 条 L2 消息 或估算 12K token，写进配置）时：

- 把最老的一批 L2 压成**一条**摘要消息（「第1~6轮概要：你杀了X，被Y过拆，身份已暴露」），插在 L1 之后
- 这次调用必然 miss 一次，之后前缀重新稳定，继续长期命中

**明确不采用**每次删最老一条的滑窗做法 —— 那会让前缀每次都变，等于永久 0 命中，是最坏解。

### 7.4 Anthropic 的显式缓存

DeepSeek / OpenAI 是自动前缀缓存，什么都不用做。Anthropic 要显式打点：在 **L0 末尾**和 **L1 末尾**各放一个 `cache_control: {"type":"ephemeral"}` 断点（上限 4 个，用 2 个）。L2 不打点。

### 7.5 让省钱可验证（不然又是一次「声称完成」）

`AIGateway.call_ai` 增加 `return_usage` 参数，把 provider 返回的 usage 提取后写 `logs/runtime/ai_cache_stats.jsonl`，每行一条：

```json
{"ts":"...","player_id":2,"provider":"deepseek","model":"...","kind":"respond",
 "prompt_tokens":3120,"cached_tokens":2944,"completion_tokens":88}
```

各家字段名不同，做兼容提取：DeepSeek `prompt_cache_hit_tokens`、OpenAI `prompt_tokens_details.cached_tokens`、Anthropic `cache_read_input_tokens`。**取不到就写 `null`，绝不用估算值冒充实测值。**

### 7.6 有意不做的

- **不跨对局持久化窗口**：上一局的身份和手牌带进新局会污染判断，省的钱不值得。
- **不做跨玩家共享 L1**：两个 AI 用同一武将时理论上 L1 也能共享，但身份不同、且要求座次表一致，收益小、出错风险大。
- **不为省钱降低思考质量**：你已明确「要 API 真思考，不要求快」。缓存只压输入侧重复部分的价格，不删任何该给模型看的信息。
