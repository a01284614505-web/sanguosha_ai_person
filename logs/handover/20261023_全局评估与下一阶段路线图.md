## 2. 代码逻辑与交互逻辑

### 2.1 做得好的地方（不要推倒重来）

- **引擎是唯一裁判**：AI 只能从引擎生成的合法列表里选索引，选错有规则 AI 兜底。这条底线让"模型胡说八道"永远不会破坏对局。
- **信息隔离严谨**：账本只记公开行为、笔记只给本人看、聊天被包成引用防伪造系统消息、prompt 导出脱敏。很多自制项目在这里漏得一塌糊涂。
- **聊天调度器设计合理**：优先级、全局并发 ≤2、单 AI 冷却、过期丢弃、决策从不等聊天、429 退避——这是正确的工程方向。
- **测试文化**：772 项测试、固定种子回归、浏览器脚本、交接六字段格式。GPT 交接文档会主动写"没有宣称脚本测试证明了模型智能提升"，这种诚实很难得。

### 2.2 AI 智力：实测发现的问题（按影响排序）

下面每条都来自 P5 代码或假模型对局抓到的真实 prompt，不是猜测。

**A1【严重】"思考模式"开关是摆设。** 档案里能存 `thinking: true`，但 `AIGateway.call_ai` 发出的请求体只有 `model/messages/temperature/max_tokens`，从不发送 `reasoning_effort` 或任何思考参数。交接文档说"thinking 开/关各一局对比待验"——按现在的代码，这两局实际上是一样的。

**A2【严重】部分模型会静默退化成规则 AI，而你很难察觉。** 决策请求固定带 `temperature`（默认 0.8），聊天固定带 `max_tokens=120`。不少推理型模型（如 OpenAI 的推理系列）不接受自定义 temperature 或旧的 `max_tokens` 字段，会直接返回 400。决策失败时引擎会无声切到规则 AI，界面只在决策轨迹里写一句"按规则选择合法候选"。也就是说：**如果你某次觉得"AI 好蠢"，有可能那一局根本没有模型在打。** 需要 (a) 按 provider/模型适配参数；(b) 在座位上明确显示"模型/规则兜底"，赛后给出兜底率。

**A3【严重】会话"前情概要"是垃圾。** 压缩逻辑取每条旧消息的**前 80 个字**拼成摘要。而每条消息开头恰好是"【出牌阶段】可以使用任意张手牌……"或"引擎负责合法性，请比较选项……"这种固定套话。实测摘要原文是一串重复的阶段说明和 JSON 碎片，没有任何"谁对谁做了什么"。假模型一局只打了 3 轮，4 个 AI 已经压缩了 13 次（窗口上限 12000 字，而单条局势消息约 1500–2400 字，一次决策就占掉一大块）。结果是：**AI 的"记忆"实际上只剩账本聚合数字 + 自己的笔记 + 最近两三条消息**，前几轮发生的具体事件都丢了。

**A4【高】每次出牌都调用两次模型。** P4 的"先独立思考、再看老玩家示例"用两个真实请求实现。抽样条件里有 `when: []` 的通用示例，所以**只要候选多于一个，就必定触发**——实测 18 次出牌决策对应 18 次额外的"独立判断"调用，100%。延迟和费用直接翻倍，而一个出牌阶段通常要连续做 3–6 次决策。这和"丝滑"的目标正面冲突。

**A5【高】每一步都要求重写全部笔记和整套分析。** 输出 JSON 依次要求 `situation / notes（每个未公开座位都要写）/ plan / how_others_see_me / reasoning / target_ids / action_index`。在同一个回合里出第三张牌时，模型还得把四个座位的身份判断全部重写一遍。这既浪费输出 token，又让模型把注意力花在填表而不是比较选项上。

**A6【高】模型看不到决策所需的关键局面信息。** 当前局势只给了体力、手牌数、装备、判定区。缺少：
- 距离与攻击范围（谁在我杀得到的范围内、谁能杀到我）——候选列表里有合法目标，但模型无法规划"先装马再杀"或"他下回合能不能打到主公"；
- 本回合已出几张杀、还能不能出；
- 行动顺序（我的下家是谁、主公还有几个人才轮到）；
- 牌堆剩余、已经公开出现过几张闪/桃/无懈（高手最基础的"记牌"）；
- 本回合到目前为止发生了什么（我刚拆了谁、他打出了什么）。

**A7【中】细节噪音与不一致。**
- L1 写"你是 AI2，身份：lord"——英文代码（#11 修过但没合入）。
- "场上角色"按内部 ID 排序，主公（1 号）看到的顺序是 4、5、2、3 号，不是座次顺序。
- 手牌写"桃(diamond12)"，候选写"♦3 闪"，花色表达两套。
- 每次都附带"公开技能=仁德[active]"——`[active]` 是实现状态标签，对模型是噪音。
- 回合外响应（被杀要不要出闪）的局势里也带着"【出牌阶段】可以使用任意张手牌…AI提示：核心决策阶段"——那是别人的出牌阶段，读起来像在指挥响应者。
- 结尾固定问"如果你是主公会怀疑谁？"，对主公本人问这句话毫无意义。
- 候选里自己的座位没有标"（你）"。

**A8【中】选择类决策（选牌、选人、确认技能）几乎没有局面。** `make_choice_decision` 的 prompt 只有目标、打法、笔记、候选，**没有手牌和场上状态**，全靠会话历史——而会话历史正如 A3 所说是不可靠的。

**A9【中】AI 的发言和行动脱节。** P1 按你的决定去掉了决策里的附带发言（为了防止泄露推理），现在 AI 只在"有人对它说话 / 有人濒死或阵亡 / 冷场"时发言。但三国杀里最自然、最有戏的发言时机恰恰是**出手的那一刻**（"我杀你是因为你拆了主公"）。这一点值得重新讨论，见 2.4。

### 2.3 从"填表"到"真正的 agent"：改造方案

你说得对："这应该像一个好的 agent，帮助模型更好地展现自己的智力。"一个好的 agent 框架有四个要素：**清晰的当前状态、可靠的记忆、先规划后执行、按事情的重要程度分配思考**。对应到我们的项目：

**① 权威当前状态（替代 A6/A7/A8）**
引擎每次生成一份结构化的"局面卡"，三种决策入口（出牌/响应/选择）共用：
- 按座次排列的全桌表：座位、名字、武将、体力、手牌数、装备、判定区、连环、是否公开身份、**与我的距离、我能否打到他、他能否打到我**、是否是"你"；
- 回合信息：第几轮、当前回合角色、当前阶段、本回合已出杀数/剩余可出、我在行动顺序中的位置；
- 牌堆信息：牌堆剩余、本轮洗牌后已公开出现的关键牌计数（闪/桃/无懈/杀）；
- 本回合事件流水（引擎生成的人话，如"2号对4号使用【过河拆桥】，弃置了【诸葛连弩】"）。

**② 可靠的记忆（替代 A3）**
不再把每次的完整局势消息堆进会话再截断。改为每次调用由三段组成：
- 固定前缀（L0 规则 + L1 角色）——保持现有缓存契约；
- **记忆块**：引擎维护的"公开事件摘要"（按轮次，每轮几行人话，旧轮次自动压成一句）+ 本人笔记 + 本人打法 + 本人最近几次决策的结论（不是全文）；
- 当前局面卡 + 本次问题。
这样每次调用的输入大小稳定可控，没有垃圾摘要，前缀照样命中缓存。

**③ 先规划后执行（替代 A4/A5）**
- **回合规划调用**（每个出牌阶段开头一次）：给完整局面，要求输出身份判断更新（笔记）、本回合计划（有序步骤，如"先拆 3 号的八卦阵 → 再杀 3 号 → 留闪防反击"）、打法、要不要说话。老玩家示例放在这里（或直接放进 L1 静态前缀，一局只付一次缓存费）。
- **步骤执行**：之后每一步只问短问题："按计划下一步是 X，仍然可行吗？选索引。"输出只要 `reasoning（短）+ action_index`。如果局势和计划出现偏差（被无懈、目标死了、摸到关键牌），才触发重新规划。
- 预期效果：一个出牌阶段从现在的 6–12 次大请求，降到 1 次大请求 + 若干次小请求；同时行动更连贯，因为每一步都服从同一个计划。

**④ 按风险分级思考**
- 真正只有一个合理选项的（只剩"结束出牌"、全是暗牌随机选）——不调用模型（已部分实现）；
- 低风险（普通出闪、弃牌阶段弃牌）——短 prompt、低思考；
- 高风险（救不救主公、无懈要不要打、濒死用桃、关键目标选择）——给完整局面卡和笔记，开思考。

**⑤ 让"智力提升"可以被测量**
没有测量，P0–P5 是否真的变聪明只能靠感觉。建议加一个**离线竞技场脚本**：固定种子和阵容，让"模型 AI × 4"对局若干场，自动记录：
- 模型兜底率、非法输出率、平均延迟、每局 token 和费用；
- 身份判断准确率随轮次的曲线（笔记已经有数据）；
- 公开事实矛盾率（如宣称能杀到距离外的人）；
- 分身份胜率（只做参考，样本小不下结论）。
先用便宜模型（如 DeepSeek、Gemini Flash）跑，每次改 prompt 前后各跑一批对比。这比"玩一局感觉一下"可靠得多，也是真正"少走弯路"的工具。

### 2.4 聊天系统

- **调度核心**：方向正确，保留。
- **【需修】聊天 `max_tokens=120` 偏小**：P1 把聊天输出改成 `intent + how_others_see_me + say` 三个字段，中文 JSON 很容易在写到 `say` 之前被截断，导致解析失败、AI 沉默。推理型模型更严重（推理 token 也算在内或字段名不兼容）。建议去掉中间字段或把上限提到 300 左右，并按模型适配字段名。
- **【需修】聊天每次都带上整个会话快照**（约 1 万字）只为说一句 40 字的话。改成 2.3② 的记忆块后自然变小。
- **【需合并】T3b**（点名回应、接话链、AI 观战）与 P 系列冲突，需在整合分支里确认已正确合并。
- **【建议讨论】行动时发言**：在"回合规划调用"里加一个可选的 `say` 字段（明确说明这是公开台词、全桌可见、用来影响别人），经过现有的公开事实校验后在出第一张牌时显示。这和之前"决策附带发言泄露推理"的问题不同：那时是没有区分"内心推理"和"公开台词"，现在有了 `reasoning` 与 `say` 的明确分工。每回合最多一句，成本几乎为零，但牌桌会立刻"活"起来。这需要你拍板。

## 3. UI：立体感、美感、丝滑、毛玻璃与游戏感

### 3.1 现状诊断（基于截图）

- **整体风格统一**（暗漆木、金线），这是好基础，不需要换配色。
- **"网页感"大于"游戏感"**：牌桌是一个平面椭圆，中间大面积空白；座位框偏小，名字被截断（"1号 小…"）；中央出过的牌是低对比的浅色小方块，一闪即淡；手牌区左侧装备栏是纯文字列表。
- **桌面端右侧聊天栏占了约 20% 宽度**，牌桌被挤小。
- **手机竖屏**布局可用但拥挤，四个对手挤在一行；横屏更接近官方。
- **已有的动画**：飞牌（420ms）、受伤抖动、回复绿光、技能名大字、阶段栏跳动、判定翻牌盖章、指向线。功能齐全但都"轻"：没有层次、没有停顿节奏、没有屏幕级的强调。
- **音效库很丰富但几乎没用**：`assets/audio` 里有火/雷/冰属性伤害、男女阵亡、装备、铁索等 50 多个音效，代码里只用到 card/click/damage/heal/die/judge 六种。

### 3.2 根因：前端拿不到"戏剧事件"

前端现在只收到 5 种语义事件：牌进弃牌堆、判定、摸牌、阶段、技能发动。伤害、回复、阵亡都是**从前后两次状态的体力差推算**出来的——所以前端不知道"谁打的、什么属性、是不是被闪掉了"。没有"杀→指向→闪→抵消"这样的事件序列，就不可能编排出有节奏的演出。

**这是最该先做的一步**：引擎补一层"演出事件"（纯展示，不影响规则），至少包括：

| 事件 | 字段 | 用途 |
|---|---|---|
| use_card | 来源、目标列表、牌（含属性） | 出牌飞向中央 + 指向线 |
| respond | 响应者、牌、针对哪张 | "闪"弹出并与"杀"碰撞抵消 |
| nullify | 无懈层数、目标锦囊 | 无懈连锁的层层盖章 |
| damage | 来源、目标、点数、属性 | 火焰/雷电/普通受击特效 + 对应音效 |
| recover | 目标、点数、来源 | 回血光效 |
| dying / save | 濒死者、施救者 | 濒死红光心跳、桃飞入 |
| death | 死者、身份、击杀者 | 身份揭示 + "反贼阵亡"印章 + 连杀播报 |
| equip / unequip | 角色、装备 | 装备入槽动画 |
| chain | 角色、横置/重置 | 铁索缠绕/断开 |
| turn_start | 角色 | 座位高亮 + 镜头聚焦 |

引擎已经有动画 ACK 机制（等前端播完或超时），演出事件可以直接复用。

### 3.3 表现层架构（让"丝滑"可控）

- **演出时间轴**：前端用一个队列按事件顺序编排，每类事件有"开始—高潮—收尾"三段，后一段可以与前一段的收尾重叠，避免一卡一卡。
- **速度档**：慢 / 标准 / 快 / 极速（极速只保留飞牌和数字）。AI 回合多、观战时间长，速度档是"舒服"的关键。
- **可跳过**：重要演出（技能大招、连杀）点击即跳过。
- **性能规则**：只动 `transform` 和 `opacity`；特效用 CSS + 少量 Canvas 粒子；尊重系统"减少动态效果"；手机端自动降一档。

### 3.4 视觉方向

**毛玻璃用在"浮在牌桌上的东西"，不要用在牌桌本身。** 苹果式毛玻璃（`backdrop-filter: blur() saturate()` + 半透明 + 细亮边 + 内阴影）最适合：弹窗、选牌面板、响应提示条、聊天抽屉、设置面板、卡牌说明浮层。这样背景的牌桌依然清晰，操作层有"浮起来"的空间感。配合暗漆金线主题时，玻璃应偏暖色调（带一点琥珀），亮边用淡金而不是纯白。注意 `backdrop-filter` 在低端手机上较耗性能，需要提供降级（纯半透明）。

**立体感来自光和层次**：
- 牌桌加一层中心聚光与边缘暗角，让视线集中在中央；
- 座位框有厚度（边框高光 + 投影），当前行动者"抬起来"（放大 + 更强投影 + 金色描边呼吸）；
- 手牌悬停/选中时上浮并轻微透视倾斜，跟随鼠标或手指有一点视差；
- 中央出牌区的牌要更大、更亮，保留最近几张而不是一闪即灭。

**游戏感来自"仪式"，不是颜色**（详见第 4 节的参考）：
- 技能发动：屏幕压暗 0.3 秒 → 武将头像菱形徽章 + 技能名书法字 → 收回；
- 阵亡：头像变灰 + 朱红"反贼阵亡"印章盖下 + 身份牌翻开；
- 连杀/关键击杀：书法大字播报（"一破·卧龙出山""三连·举世皆惊"一类，名称可以自己起）；
- 濒死：座位红光心跳 + 全桌求桃提示；
- 主公登场：开局主公亮将有一次专属亮相。

## 4. B 站参考：游卡三国杀值得学的与要避开的

参考了十周年身份场录像（BV1x3eGe9EvV）、OL 军八心理战录像（BV17g411s7Pa）及评论区、军六改版讨论（BV1PxpR6WEvp）的评论。

**值得学**
1. **技能演出的"三段式"**：压暗 → 武将菱形徽章 + 书法技能名 → 收回，整体约 1 秒，信息明确、仪式感强。
2. **书法大字是三国杀的灵魂**：OL 的"一破·卧龙出山""三连·举世皆惊"连杀播报、大写"破"字的锦囊特效，比任何发光粒子都更"三国"。
3. **阵亡印章**：朱红"反贼阵亡"盖在灰掉的头像上，一眼看懂局势。
4. **左上角身份计数 + 目标提醒**：OL 一直在左上角显示"主×1 忠×2 反×4 内×1"和本身份目标（"找出反贼忠臣，最后击败主公"）。我们的 AI 有目标提示，真人反而没有。
5. **座位下方的座次数字**（一、二、三…）与中央出牌的文字说明（"甲对乙使用"），降低认知负担。
6. **选将界面**：主公已选武将在左侧展示、"你的身份"同屏可见、倒计时条——正好对应我们计划中的正式选将。

**要避开**
1. **数值膨胀导致"你方唱完我方唱"**：十周年评论区最高赞是"哪边的阎王先动手，哪边就赢"、"后置位活不到出牌"。我们坚持经典/界限强度是对的；新增武将（Stage 8 导入）要有强度检查。
2. **动画过长拖慢节奏**：十周年动画华丽但一局很长。我们的 AI 回合本来就要等模型，**演出必须可加速、可跳过**。
3. **内奸角色体验差**：评论反复提到"内奸是摆子/天使内"。我们的 AI 内奸目标提示词（#11）要尽快合入，并在竞技场里专门观察内奸行为。
4. **主公无脑选强将**：正式选将要做好，主公先亮、其余人看主公后选，策略才会出现。

### 5.2 趣味性与竞争力：我们和市面自制三国杀的区别

一款好游戏，核心是**有意义的决策 + 及时清晰的反馈 + 让人想再来一局的理由**。市面上的自制三国杀（无名杀等）强在武将数量和规则覆盖，弱在对手：AI 是脚本，不会说话、不会骗人、不会读你。**我们唯一真正的护城河，是"会说话、会撒谎、会读人的 AI 对手"。** 所有新功能都应该围绕它，而不是去比武将数量。

建议的功能（按"投入小、体验提升大"排序）：

1. **赛后"读心复盘"**：结算时翻开所有身份，按轮次展示每个 AI 当时对你和别人的判断（笔记已经有数据）、它的打法变化、它说过的谎。这是我们独有、别人做不出来的内容，也让玩家学到东西。
2. **心理战反馈**：你在席间说的话被 AI 当作证据处理。赛后可以显示"你那句'我是忠臣'让 3 号把对你的怀疑从高降到中"。让玩家感到"我的话有分量"。
3. **难度梯度**：规则 AI（新手）→ 便宜模型（普通）→ 强模型 + 思考（困难）。现在只有"有 Key / 没 Key"两档。
4. **观战与节奏工具**：速度档、"跳到我的回合"、AI 回合时显示一句"思考中…（已用 X 秒）"和简短的行动预告，等待不再焦虑。
5. **残局挑战**：参考"七步杀"解谜——预设局面、限定步数，纯规则、无需模型、零成本，适合碎片时间，也是检验引擎的好素材。
6. **高光时刻**：自动标记一局里的关键事件（反杀、一回合两杀、濒死被救、关键无懈），结算页回放。
7. **称号与档案**（P5 已做）：继续保持"AI 选手像真人玩家一样成长"的感觉；后续可以加跨局经验（让 AI 选手读到自己上一局的复盘要点）。

**明确不做**：抽卡、付费、体力限制等任何与金钱相关的设计（非商业项目）。

### 5.3 其他补充

- **成本面板**：每局显示各 AI 的调用次数、token、估算费用和兜底率（token 统计已有，缺展示）。
- **存档恢复**：手机切后台容易断线，对局能从快照恢复会大幅提升手机体验（F4，但对你的使用场景优先级应该提前）。
- **新手引导**：第一次进入时用一局"教学局"讲解基本操作，三国杀规则对新人门槛很高。
- **无障碍与手机热区**：按钮最小 44px，常用操作放拇指区。

## 6. 少走弯路：开发与游玩两方面

**开发**
1. 唯一主干：先把整合分支推上来并合入 main，清理过期 PR。
2. 先补"测量工具"（竞技场、兜底率、演出 ACK 延迟），再做优化——否则每一轮改动都无法证明有效。
3. 先修"喂给模型的东西"（局面卡、记忆、参数适配），再调 prompt 措辞；措辞调优的收益远小于信息完整性。
4. 先补"演出事件"，再做特效；否则特效只能贴在推算出来的状态上，越做越别扭。
5. 每批有冻结契约和验收清单，长任务模型才不会跑偏。

**游玩**
1. 等待时间是 AI 对局最大的敌人：回合规划（减少调用）+ 速度档 + 思考提示，三管齐下。
2. 每一个重要结果都要有"看得见、听得见"的反馈（音效库已经在那里了）。
3. 让玩家理解 AI：复盘与读心报告把"AI 为什么这么打"变成乐趣而不是困惑。

| T3b 与 P1–P5 冲突合并 | 交接称保留了 P1 独立发言通道、事实校验与隐私闸门 | 测试通过，**实机待验** |
| 皮肤 | 已实现浏览器本地版 | 见 10.4 |

### 10.3 局面卡（D 批）：方向对，但现在的写法会让模型更糊涂

D 批的初衷与本文 2.3① 一致，但用假模型对局抓到的真实 prompt 暴露出三个问题。

**问题 1【严重】：局面卡用内部编号，不是座位号。** 新增的"【引擎权威当前公开状态】"JSON 里，`distances` 以内部 ID 为键（如 `"0":{"1":1,"2":2}`）。`current_player_id`、笔记里的 `target_id` 也是内部 ID。而同一条消息里又要求模型"target_ids 填座位号"，旧文字局势也用座位号。P0 花了一整批统一座次，这里又把内部编号送回了模型眼前。比如主公看到距离表里的"2"，实际指的是 1 号位的自己。模型很容易把"2号"读成座位 2。

**问题 2【高】：新旧两份局势同时发送，输入长度翻倍。** 新 JSON 加在原有文字局势前面，旧的"场上角色/你的手牌/阶段说明"没有删除。实测出牌决策的末条消息从约 2400 字涨到约 5200 字；一局 3 轮的压缩次数从 13 次涨到 26 次。A3 的垃圾摘要因此出现得更频繁。

**问题 3【中】：JSON 是给程序看的，不是给模型看的。** 里面有 `state_version` 哈希、`card_move_seq`、`schema_version`、手牌的 `"id":"standard_tao_diamond_12_1"` 和 `"image":"tao"` 等字段。对诊断有用，对模型是噪音，还占 token。

**建议的写法**：保留 `public_situation.py` 作为唯一数据源，诊断日志照常用完整 JSON。另写一个"给模型看的渲染"：
- 按座次排列，全部用座位号；
- 一行一人，标出"（你）"、"距你 X / 你能否打到他 / 他能否打到你"；
- 手牌用"0:♦Q 桃"统一格式；
- 删掉旧的文字局势，两份只留一份。

### 10.4 皮肤系统（F1 本地版）

**实现方式**：
- 图片存在浏览器的 IndexedDB 里，按武将 ID 绑定一张；
- 支持导入本机 PNG/JPEG/WebP，有真实文件头、尺寸、大小校验；
- 另提供 noname 仓库某个固定历史提交里，与本项目 27 名武将对应的 307 张原画候选，预览或导入时才从 GitHub 原始地址下载；
- 对局页通过监听页面元素，把带武将 ID 的头像替换成本地皮肤。

**做得好的**：
- 文件校验严谨；
- 来源和版权边界写得诚实（注明 GPL 仓库许可不等于原画授权）；
- 失败时回退默认立绘；
- 没有一次性塞进 300 多张图。

**问题与建议**：
1. **【高】皮肤只存在当前浏览器。** 你电脑浏览器和手机都在玩，现在要分别导入一遍，清理浏览器数据就没了。你已经有服务器端的档案（profile_id）和 AI 档案，建议皮肤选择也按档案存到服务器，图片放在服务器资源目录里按需复制。原计划 9B 就是这个设计。
2. **【高】在线候选依赖 `raw.githubusercontent.com`。** 这个域名在国内网络经常打不开或很慢，预览可能一直失败。建议改为由游戏服务器代为下载并缓存，浏览器只访问自己的服务器；或者提供一个一键下载脚本，在电脑上先把 307 张拉到本地资源目录。
3. **【中】页面是"开发者工具"形态，不是"玩家换皮肤"形态。** 截图里需要手动输入英文武将 ID（"例如 caocao"），页面一打开就显示红字"武将 ID 格式无效"，主要操作是下拉框和"扫描并预览"。建议改成：
   - 武将头像网格 → 点击武将 → 该武将所有皮肤缩略图画廊 → 点击即换（毛玻璃浮层很适合这里）；
   - 选将界面在武将卡上加"换皮肤"小按钮；
   - 文件导入作为画廊里的最后一格"＋自定义"。
4. **【中，需实机确认】可能闪烁**：对局页每次刷新座位都会先放默认图、再异步换成皮肤。状态更新频繁时，可能看到头像闪一下。
5. **【低】"379 张"已明确找不到**，GPT 如实写了是 307 张，不要再把 9B 按 379 张验收。

### 10.5 新模式（八人、2v2、斗地主）：模型 AI 的提示词没有跟上

后端规则和规则 AI 各有 10 局完整对局记录，前端也接上了。但模型 AI 的提示词仍是按身份局写的：
- L0 固定写着"身份局胜负：主公与忠臣需杀光反贼与内奸……"；
- 2v2 和斗地主的身份是 `team_a` / `landlord` / `farmer`。`goal_block` 里没有这些身份的目标，只会输出一句"依据你的身份争取胜利"。
- 它还会对**身份公开**的模式说"只有你知道自己的隐藏身份……你可以说谎跳身份"。

结论：新模式目前只适合规则 AI；用模型 AI 打这三个模式，会拿到错误的胜负说明。需要按模式生成 L0 胜负规则与目标说明（ModeSpec 里已有 `victory`、`identities_public` 字段可以直接用）。

### 10.6 其余新增（简评）

- **规则 A 批**（判定后放先判、翻面跳过整回合、酒自救）和 **C 批规则 AI**（闭月/奸雄等会发动、救援有判断）：解决了第 2.6 节的 4 条欠账。这对"无 Key 模式"和"模型失败兜底"的体验提升很大。
- **阵亡后三选 + 只读观战 + 后台结算**：对应你之前定的死亡流程，测试和浏览器记录齐全。
- **F4 存档恢复**：整回合安全点。对手机切后台的场景很有价值；交接如实写了"不保证任意时刻零丢失"。
- **F6 TTS**：浏览器语音播报公开事件，非阻塞。适合做成"解说"开关，但要注意和音效、动画的节奏配合。
- **技能试验台 + 10 项对照认证**：Stage 8 的质量把关做得认真。

### 10.7 第二轮后的优先级调整

在第 8 节顺序上微调：

1. **批次 1 扩大**：参数适配和兜底可见（不变），**加上**修 D 批的内部编号问题、删掉重复的旧文字局势。这两项都很小，却直接影响模型能否读懂局面。
2. 新增**模式感知提示词**（10.5），排在竞技场之后、agent 化改造之前；或者并入 agent 化改造一起做。

## 11. 与 GPT-6 Astra 上下文方案的对照，以及合并版方案

你转来的 Astra 方案共 7 步：
1. 统一由引擎生成最新局势；
2. 固定世界书与每个 AI 的动态记忆分开存，动态记忆扩展现有认知笔记；
3. 模型在返回行动时一并返回记忆修改，按条目覆盖、不变的不重复写；
4. 停止堆积历次局势，只保留固定前缀、一份最新局势、当前记忆和最近一小段原始事件，删旧事件前先确认记忆已处理到哪个事件号；
5. 每次结算后由引擎写实际结果；
6. 聊天接入同一份局势与记忆；
7. 发送前检查长度，按优先级裁剪，必需内容超限时明确失败、走兜底。

下面按"可以直接采纳 / 需要补强 / 我不同意或建议改动"来说。

### 11.1 可以直接采纳的（比我第一轮写得更具体）

- **记忆按条目增量更新**：身份判断按座位覆盖，计划只留一份，不变的不要求重写。这比我第一轮"每个出牌阶段开头统一重写笔记"更省，也同样解决 A5。**采纳。**
- **"处理水位线"**：删旧事件前，先确认记忆已经更新到哪个事件号，没处理过的事件不能当成已总结丢掉。这是防止"失忆"的好设计，我第一轮没写。**采纳。**
- **每一手的实际结果回灌**：是否被响应、抵消、取消，造成的伤害、牌移动、事件号，都由引擎从已完成的结算中取，不让模型自己推算。现在的回灌只有一句"你的操作 play_card 已生效"，这一条正好补上。**采纳。**
- **发送前预算检查与裁剪顺序**：先减旧聊天，再减旧事件，再减无关规则说明；合法选项和当前局势绝不截断，超限就明确失败、走兜底。**采纳**，它也解决了 GPT 自己台账里写的"超大单条当前状态可使输入超过阈值"。
- **聊天共用同一份局势与记忆**，不另建"聊天记忆库/承诺数据库/外交代理"。这和我"聊天每次带整段会话太贵"的结论一致。**采纳。**
- **不引入新数据库或 agent 框架，在现有模块上改**。**同意。**

### 11.2 需要补强的（Astra 方案没有覆盖）

1. **调用结构没变，"丝滑"问题没解决。** Astra 方案仍然是"每个微决策一次完整调用"，也没有提 P4 每次出牌两次调用的问题。上下文变干净了，但一个出牌阶段仍要 6–12 次大请求。**补**：回合规划 + 步骤执行（2.3③），并取消 P4 的第二次调用，把老玩家示例放进 L1 固定前缀或回合规划里。
2. **前置条件：参数适配和兜底可见（A1/A2）。** 如果模型因参数不兼容一直在走规则 AI，上下文改得再好也看不到效果。**补**：放在最前面。
3. **"给模型看的局势"必须用座位号、去掉诊断字段。** Astra 说"引擎返回公开状态"。现有实现正是把诊断 JSON 直接塞给模型（10.3）。**补**：明确要求有一层"模型渲染"。
4. **按风险分级思考。** 救不救主公、无懈要不要打，与普通出闪不应该花一样的成本。**补**：2.3④。
5. **测量。** 没有竞技场，就无法证明这套改造让 AI 更强。**补**：2.3⑤，先于大改造落地。
6. **模式感知。** 新增的三个模式需要不同的胜负与目标说明（10.5）。

### 11.3 我不同意或建议改动的

**"重要事件由模型挑选编号来记住"——建议改成"客观史由引擎记，主观判断由模型记"。**

Astra 方案让模型在回复里返回"需要继续记住的事件或发言编号"，旧事件只保留被引用的。顾虑有两个：
- 模型挑编号容易漏、容易引用错，而且漏掉的事件之后就永远看不到了；
- 每个 AI 都要额外输出这些编号，增加输出负担。

建议的分工：
- **公开史（客观）**由引擎维护一份按轮次的人话摘要，所有 AI 共享同一份。旧轮次自动压成一两句，比如"第 2 轮：3号杀主公两次，5号救主公一次"。这部分不花模型 token 去生成，也不会漏。
- **个人记忆（主观）**由模型维护：身份判断、当前计划，加上可选的"钉住"少量条目（最多 3–5 条，主要用于记住某句关键发言，如"4号第2轮说自己是忠臣"），每条附一句为什么重要。

这样既保留了你提的"每个 AI 有自己的世界书条目"，又不把"记住发生过什么"这种客观工作交给会出错的模型。

### 11.4 合并版：一次调用的组成

```
[L0 固定] 规则、卡牌表（按模式生成胜负说明）                  ← 整局不变，可缓存
[L1 固定] 我是谁、我的武将与技能、对手技能、老玩家经验示例      ← 整局不变，可缓存
[记忆]   公开史摘要（引擎）+ 我的判断/计划/钉住条目（模型增量维护）
[现在]   局面卡（座位号、距离/射程、杀次数、牌堆与记牌、我的手牌）
[刚才]   我上一手的实际结果 + 自我上次调用以来的新事件 + 新桌聊（≤N 条）
[问题]   本次任务与合法选项
—— 发送前预算检查：按优先级裁剪；必需内容超限 → 记录失败 → 兜底
```

**调用类型**：

| 类型 | 时机 | 输入 | 输出 | 思考 |
|---|---|---|---|---|
| 回合规划 | 每个出牌阶段开头 | 全部 | 记忆增量 + 本回合计划 + 可选公开台词 + 第一步 | 开 |
| 步骤执行 | 计划内的后续每一步 | 现在 + 刚才 + 计划 | 短理由 + 索引；偏离计划时请求重新规划 | 关或低 |
| 高风险响应 | 救主公、关键无懈、濒死用桃等 | 全部 | 理由 + 索引 + 可选记忆增量 | 开 |
| 普通响应/选择 | 其余 | 现在 + 刚才 + 记忆 | 理由 + 索引 | 关或低 |
| 聊天 | 调度器触发 | 记忆 + 现在（精简）+ 最近桌聊 | 一句台词 | 关 |

**落地顺序**（按"每步都能单独验证"排）：
1. 参数适配 + 兜底可见；
2. 竞技场；
3. 模型渲染层（座位号、去重复）+ 实际结果回灌；
4. 公开史摘要 + 个人记忆增量更新 + 水位线，替换旧摘要；
5. 发送前预算；
6. 回合规划/步骤执行 + 取消 P4 双调用 + 风险分级；
7. 聊天切到同一套输入；
8. 模式感知提示词。

每一步做完都用竞技场对比延迟、费用、兜底率、判断准确率，再进入下一步。

### 11.5 需要你拍板的分歧点

- **公开史谁来记**：引擎记（我的建议），还是模型挑编号记（Astra 的建议）。也可以先按我的方式做，竞技场里观察 AI 是否经常"忘事"，再决定要不要加模型挑选。
- **回合规划里要不要带一句公开台词**：与第 7 节第 2 项相同。
