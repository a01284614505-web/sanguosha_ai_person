# 日志与交接规范

## 目录职责

- `CHRONICLE.md`：主编年史与交接索引，保留在日志根目录。
- `handover/`：每次任务完成后的说明交接日志及已批准方案。
- `runtime/`：服务器标准输出、错误输出和历史运行日志。
- `reports/`：自动化测试、WebSocket 回归和验收 JSON 报告。
- `archive/`：已过时但需要保留的结构说明和设计文档。

## 交接日志必填项

文件名：`YYYYMMDD_HHMM_<任务名>.md`

每份日志必须注明：

1. 执行模型 ID。
2. 任务开始和结束时间戳（含时区）。
3. 实际改动文件清单。
4. 检测命令与未经美化的真实输出。
5. 每项检测的结论：通过、失败、未检测或预存问题。
6. 后续预期与遗留事项。

不得把方案、预期或未执行测试写成完成结果。检测失败时保留原始错误摘要，不得只写“基本通过”。日志中不得包含 API Key、Token、密码或私钥。

## 专职代理

项目代理 `.claude/agents/log-curator.md` 负责日志整理、交接文件和 CHRONICLE 索引维护。该代理只处理日志文档，不修改运行代码。
