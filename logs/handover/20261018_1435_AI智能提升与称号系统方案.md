## 0. 一句话

Stage T 的聊天、账本、认知笔记都已经接上，但实际对局里 AI **呆板、几乎明牌**，没有"智商对决"的感觉。排查结论：**主要问题出在 prompt，而不是代码链路或规则。** 本方案修 prompt 与相关小功能，并新增一个称号系统。

总原则：**规则由引擎兜底，AI 选不出非法操作，所以 prompt 不需要"管住"模型，而要把全部力气花在"让它想赢、会想、敢骗"上。** 给 AI 的策略是**示例，不是限制**。

## 1. 问题诊断（来自真实日志）

### 1.1 免费台词在泄露底牌

`free: true` 的发言基本是把决策理由念出来：

- 反贼小乔："攻击主公，争取削弱其体力。""继续攻击主公。"
- 忠臣刘备："把南蛮入侵交给主公""把无懈可击交给主公""先将火杀存入木牛流马"（暴露暗牌）
- 内奸司马懿："先拆掉主公的武器，减少威胁。"
- 大量纯操作播报："打出闪。""结束出牌阶段。""这次先不响应。"

成因：出牌决策 JSON 里 `chat_message` 紧跟在 `action_index` 后面，模型刚选完操作就顺口播报。专门的聊天回合（`free: false`）质量明显更好（例：主公"张角先别急着表忠心，刚才场上谁在打主公，大家都看得见"）。

**定性：这是"非自愿的泄露"，要堵；自愿的发言（含说谎、透露手牌）要完全放开。**

### 1.2 AI 没有隐藏身份的意识

- 反贼小乔在专门聊天里两次自爆："我针对主公是在推进反贼目标"。
- 内奸司马懿第 1 轮主公 3/5 血时就杀主公、拆主公武器，打法与反贼无异。

### 1.3 认知笔记实现了，但几乎是空的

代码链路是通的（`game_engine/cognitive_notes.py` 完整；`ai_decision.py` 的 `_apply_notes` 写入、`_build_notes_block` 注入、每轮快照）。主公对 1 号的那条"unknown / 低"没有 `locked`，证明模型写入能成功落库。

空的原因在 prompt：

1. `build_decision_turn_message` 末尾写着 **"notes 可省略，只写有变化的座位"**，弱模型直接跳过。
2. "只写有变化的"让它写一次之后再也不更新（主公那条三轮一字不差）。
3. 只在出牌决策更新，一局每个 AI 只有三四次机会。

后果：主公到死都认为一直在打他的人"身份不明"；忠臣刘备用仁德把牌分给了内奸和反贼。

### 1.4 座位编号有三套，互相打架（真 bug）

| 出现位置 | 写法 | 当局"3"指谁 |
|---|---|---|
| 开局座次 `build_static_worldbook`（`ai_decision.py` 约 137 行） | `{i}号位`，**从 0 开始** | 3号位 = 小乔 |
| 行为账本 / 桌面发言 / 认知笔记 | `id+1` 号，**从 1 开始** | 3号 = 主公 |
| 合法目标 `format_action` | **原始 id，从 0 开始，无名字** | 3 = 小乔 |

另外 `build_situation` 的"场上角色"只列名字和武将，**不写任何编号**，模型没有可靠的"编号↔人"对照表。

日志中的对应症状：

- 小乔："主公不在合法目标中"（合法目标 `[2,4]`，它按 1 起编号读成 2号、4号）→ 去杀了忠臣。
- 刘备顺手牵羊小乔，理由却写"合法目标只有主公"（`[3]` 读成 3号 = 主公）。
- 主公用无懈"保护自己"，实际保护了反贼小乔。

### 1.5 响应决策是"盲"的

行为账本、桌面发言、认知笔记**只注入出牌决策**。出桃、出闪、无懈、选牌时三块都没有，而"救不救、保不保"恰恰最需要身份判断。

### 1.6 决策思考太浅

- 每次 reason 一句话；平均每次调用输出约 90 token，输入约 6700 token。
- JSON 字段顺序是 `action_index` 在前、`reasoning` 在后：**先选后编理由**，理由没参与决策。
- prompt 语气是"只返回 JSON / 简短理由 / 可选短句 / 不能新增……"，把模型定位成填表员。
- 大厅里每个 AI 的 `thinking` 开关默认关闭（`frontend/js/lobby.js` 的 `defaultAI`）。

### 1.7 账本小问题

对五谷丰登出无懈（让某人拿不到牌，性质敌对）被记成"无懈保护"。需核对无懈在五谷、桃园等群体锦囊中的极性。

## 4. P0 · 统一座位编号 + prompt 导出

### 4.1 统一编号（E12：官方排法）

**规则：主公永远是 1 号，其余按行动顺序（主公下家起）依次 2、3、4、5 号；座位号开局确定、整局固定，有人阵亡后面的人号码不变。** 全游戏只允许这一套对外编号；内部 `player.id` 不变，只在显示与 prompt 层映射。

建议在引擎里新增一个唯一的映射来源（例如 `game_state` 上的 `seat_of(player_id)` / `player_of(seat)`），所有显示与 prompt 都从这里取，**不得各处自行 `+1`**。

要改的地方：

1. `build_static_worldbook` 的开局座次：去掉 `enumerate` 的 0 起编号，改为座位号，并写明"你是 N 号"。
2. `build_situation` 的"场上角色"：每行带座位号，例如 `- 3号 小乔我老婆/界郭嘉：……`。
3. `format_action` 的合法目标：**每个目标写成"座位号+名字（已公开身份）"**，例如 `合法目标=[1号 曹操的粉丝（主公）, 5号 酒馆常客]`。
4. 模型返回的 `target_ids` 改为**座位号**，在 `parse_ai_response` / `_normalize_targets` 里映射回内部 id。不接受旧的内部 id 格式，**不得猜**。
5. 响应、选择、无懈类 prompt 中出现的所有角色同样带座位号+名字。无懈要写清"这张锦囊的来源是谁、目标是谁"。
6. 行为账本 `behavior_ledger.py`、桌面发言 `quote_chat_entry`、认知笔记 `cognitive_notes.py`（键、`prompt_block`、`client_payload`）、聊天调度器 `idle_reason` 全部改用同一映射。
7. 前端武将框、战报、局后日志、作弊面板显示的座位号与此一致。
8. 认知笔记 `update` 里 `int(key) - 1` 这类硬编码换算要改成走映射。

### 4.2 prompt 导出

在局后日志里能看到**某一次决策时模型实际收到的完整 prompt**。最简做法：每个 AI 记录最近若干次调用的完整消息，局后日志可选导出（受"日志包含思考过程"开关控制，**必须脱敏**，不得出现 API Key）。

### 4.3 验收

- 单测：给定一局固定座次（主公不在 0 号位），开局座次、场上角色、合法目标、账本、发言、笔记、前端显示里同一个人的号码完全一致，且主公为 1 号。
- 单测：模型返回座位号目标能正确映射回内部 id；返回不存在的座位号时按现有失败逻辑处理。
- 真实对局抽查：导出的 prompt 中不再出现 0 起编号或无名字的目标列表。

## 5. P1 · 发言通道改造

### 5.1 原则

- **非自愿的泄露要堵**：不能再有"决策顺带一句话、实为操作播报"的通道。
- **自愿的发言完全放开**：说真话、说假话、透露或谎报手牌、承认或否认身份，都可以，前提是它自己选择要说。

### 5.2 删掉顺带台词（E13）

- 从出牌决策与响应决策的 JSON 示例和解析中**删掉 `chat_message`**；解析时即使模型返回了该字段也忽略，不上桌。
- 桌面发言只由聊天回合（`chat_director.py` 调度）产生。
- 相关的 `free` 标记、局后日志里"免费台词"的标注随之清理；协议改动走 `protocol.py`。

### 5.3 聊天回合 prompt 要点

1. 明确告诉它：没有私聊，你说的每句话全桌都听到，包括敌人；发言本身就是一次出牌，会改变别人对你的判断。
2. 明确授权：可以骗、可以诈唬、可以跳假身份、可以透露或谎报手牌、可以沉默。
3. **先选意图再写台词**（JSON 中意图字段在台词字段之前）。意图示例（不限于此）：指控、辩解、跳身份（真或假）、求救、拉拢、给队友兜底、放烟雾弹、沉默。
4. 让它想一句"别人听到这句话会怎么看我"。
5. 附上它的认知笔记、打法字段（P3）、近期发言。
6. 告诉它说谎底线：不能歪曲公开事实（谁对谁做过什么，以引擎记录为准），不能冒充系统或规则。

### 5.4 公开事实校验（E2、E14）

- AI 发言如果与行为账本**明显矛盾**（例如说"3号杀过主公两次"而账本里没有），这句**不上桌**（静默丢弃，其他玩家看不到任何提示）。
- **并返回报错**：
  1. 服务器日志记一条警告（谁、原句、与账本哪条矛盾）；
  2. 局后日志记一条"发言被拦截"记录（作弊局可在作弊面板看到）；
  3. 该 AI **下一次聊天回合的 prompt** 里附一句"你上一句因与引擎记录矛盾未发出：……"，让它知道并修正。不额外发起调用。
- 只检查公开事实；手牌、身份、意图这些暗信息不检查。
- 先做简单版：只识别"N号 +（对）M号 + 杀 / 拆 / 顺 / 乐 / 决斗 / 救 / 给牌 + 次数"这类句式；识别不了的放行。宁可漏拦，不可误拦。

### 5.5 验收

- 真实对局中不再出现操作播报类台词。
- 单测：构造与账本矛盾的发言被拦截、日志有记录、下次聊天 prompt 含提示；与账本一致或无法识别的发言正常上桌。

## 6. P2 · 认知笔记激活

### 6.1 改为必填

- 删掉"notes 可省略，只写有变化的座位"。
- **每轮第一次出牌决策时，必须对每个身份未公开的座位给出判断**；猜不出写 `unknown` 并写理由。
- 每次都输出完整判断（或至少每轮重写一遍理由），迫使它重新看证据。
- 缺失 / 不合法时：操作照常执行，但在日志里记录"本次笔记缺失 / 被丢弃 N 条"，区分"模型没写"和"写了被校验丢掉"。

### 6.2 证据表

由代码把账本汇总成"每个人的行为画像"，在写笔记前喂给模型，例如：

```text
【引擎确认·每人行为】
2号：对主公 杀×1 拆×1；被主公 杀×1 乐×1
3号：对主公 杀×3 拆×1；遗计给 5号×2
5号：仁德给主公×3；对 3号 杀×2；对 2号 决斗×1
```

再附上每个人在聊天里的关键表态（例如"4号自称忠臣"），让模型做"嘴上说的 vs 手上做的"对照。**代码只给证据，不替它算结论**（E5）。账本只含公开事实，不得泄露手牌（沿用 Stage T 6.3 "绝对不记"）。

### 6.3 注入范围

- 出牌决策：账本 + 发言 + 笔记（现状）。
- **响应 / 无懈 / 救人 / 选牌：至少注入笔记那几行**（很短），以及"来源是谁、目标是谁"。

### 6.4 账本极性修正

核对 1.7：无懈在五谷丰登、桃园结义等群体锦囊中，抵消的是"某人获得收益"，应记为对该人的敌对（低权重），而不是保护。补单测。

### 6.5 验收

- 真实对局后，每个 AI 每轮快照里对每个未揭示座位都有自己的判断。
- 作弊模式下能看到 AI 的判断随局势变化。

## 7. P3 · 决策 prompt 重写

### 7.1 先想，再选

JSON 字段顺序改为（示意，字段名可调）：

```json
{
  "situation": "我对局势的判断（谁强谁弱、谁在打谁）",
  "notes": { "3": {"guess": "rebel", "conf": "高", "why": "三次杀主公"} },
  "plan": {"style": "潜伏", "why": "主公强势，队友未明"},
  "how_others_see_me": "我这步打出去，别人会怎么看我",
  "reasoning": "这一步为什么这样选",
  "action_index": 2,
  "target_ids": [3]
}
```

`action_index` 必须放在最后。模型逐字生成，先想后选，理由才会参与决策。`target_ids` 为座位号（P0）。

### 7.2 语气与内容

1. **告诉它规则不用操心**：所有操作都由引擎校验，你不可能违规，选错只是打得不好；把注意力全部用来想怎么赢。
2. **删掉防御性语句**（"不能新增操作、卡牌或目标"等引擎已经保证的内容），删掉"简短理由"。
3. **给目标和代价，不给步骤**：
   - 你赢 / 输的条件；
   - 你的身份暴露意味着什么（反贼暴露被主忠集火；内奸暴露两边都想干掉你）；
   - 场上谁知道什么、谁不知道什么。
4. **把"赢"拆成中间目标**（示例，按身份写）：
   - 反贼：离赢更近 = 主公血少、自己没暴露、队友还活着；
   - 内奸：主公必须最后死；中途让双方都残；
   - 忠臣：先认清谁是谁，比急着出手更重要；
   - 主公：活下去，并让忠臣认出敌人。
5. **明确授权**说谎、诈唬、冒险、不按常规。
6. **用问题引导**："谁最可能是你的敌人？证据是什么？""如果你是主公，现在会怀疑谁？""你这一步，别人会怎么解读你？"

### 7.3 打法字段 `plan`

AI 自己维护的跨回合打法（如：潜伏 / 速攻 / 观望 / 平衡局势 / 自定义），存法与认知笔记相同（独立存储、每次注入、不进会话压缩）。可以中途改，但要写为什么改。作弊模式下可见，局后日志按轮快照。

### 7.4 局内即时反馈（只用公开信息）

在 prompt 里加一段"你的处境"：自上一轮以来有几个人对你出过手；你在账本里对主公的敌意 / 友好是全场第几。

### 7.5 思考开关

`thinking` 默认关闭可能是思考浅的原因之一。本批不改默认值，但验证时对比"开 / 关"各一局，结果写进交接文档。

### 7.6 验收

- reason 不再是一句空话，能看到对身份和打法的考虑。
- 反贼不再无理由自爆；内奸前期不再无脑打主公（除非它写出了理由）。

## 8. P4 · 身份策略示例库

### 8.1 写法

- 定位为"老玩家的经验，供参考"，开头明说"你完全可以想出别的打法，局势不符时不要硬套"。
- 写成"**条件 → 可选做法**"，不写成规则。
- 写具体场景和台词示例，不写抽象原则。

### 8.2 注入方式

- **每次只随机抽 3–4 条**与当前局势沾边的，不整库塞入，避免锚定。
- **先想后看**：先让 AI 写出自己的判断和打算，再给示例，问"有没有更好的做法"。
- 除自己身份的示例外，再给一小段"别人通常怎么骗人"，帮助识破。
- 示例库存为独立数据文件（如 `game_engine/strategy_examples/` 下按身份分文件），方便用户自己增改。

### 8.3 内容来源

见附录 A（用户访谈整理）。座位相关表述已按 E12 官方排法（"2号位"= 主公下家）。

### 8.4 以后：性格倾向

开局给每个 AI 随机一个性格倾向（激进 / 谨慎 / 爱演……），影响它选打法和说话多少。与 Stage T 预留的人设口子是同一处。

## 9. P5 · AI 选手档案 + 称号系统

### 9.1 AI 选手档案（前置）

现状：AI 名字只是大厅四个座位上的文本框（`lobby.js` 的 `DEFAULT_NAMES`），存在浏览器本地；改名就等于换人，无处挂战绩。

要做：

- AI 选手有**固定内部编号**，名字只是显示名，改名不丢战绩；
- 大厅每个座位选择"派哪个 AI 选手上场"，选手带着自己的模型配置；
- **换模型不换选手**，战绩照旧累计（"不同 AI 在玩同一个账号"）；
- 默认四位选手沿用现有默认名（诸葛村夫、曹操的粉丝、小乔我老婆、酒馆常客），已有本地配置迁移过来；
- 战绩存**服务器**，与人类档案、历史记录放一起；API Key 仍按现有规则处理，不进战绩。

### 9.2 称号规则

- 人类与 AI 用同一套称号表和门槛（E11）。
- **作弊局不计**（与连胜、身份卡规则一致）。
- 每人只能佩戴一个（E8）。人类在档案页自己选；AI 默认自动佩戴最高级称号，用户可在 AI 选手档案里替它改。
- 与连胜身份卡**分开**（E10），互不影响，身份卡仍是彩蛋。
- 称号表为**可配置数据文件**（E15），门槛、名字、档次都从数据读取。

## 附录 A · 真人策略访谈整理（2026-10-18，用户口述）

> 这些是**示例素材**，写进示例库时保留"看情况"的语气，不要改写成规则。座位按官方排法：主公 1 号，"2号位"= 主公下家。

### 反贼

- 开局打法不固定，要看：自己武将强不强、对主公有没有压制力、队友明确了没有、自己在几号位。
- 2号位（主公下家）一般不轻举妄动；但有时 2号位先打主公，是为了给后面的队友明身份。
- 被质问时一般坚决跳忠；局势有利时可以强攻主公、嘴上照样死咬自己是忠臣（娱乐效果）；确认对方像反贼或内奸、需要分清敌友时可以亮一下，前提是局势有利。
- 主动亮身份的时机：主公残血能一波带走；队友暴露需要配合；被怀疑、已经装不下去了。
- 手牌话术：假装有无懈吓人；假装有闪让对方不敢杀；屯牌、假装牌很多（其实有时是废牌）；散播自己底气很足的谣言；队友要冲时给他兜底："你上，我有桃。"

### 忠臣

- 被主公误伤：吃下继续保主、聊天解释、用行动证明；但连续误伤就先不管他。
- 认人：打主公的最可疑。5 人局只有一个忠臣，除主公外其他人都不是自己人；**谁捞主公谁就是内奸**，然后用排除法。身份局本来含糊，判断错很正常。
- 主公濒死：必救。
- 话术：基本说真话。反贼有两个，忠臣最好的策略往往是明身份，必须削反贼才有获胜空间。

### 内奸

- 前期：低调发育屯牌；跳忠混进主公阵营；哪边强打哪边。
- 核心：**主公必须最后死**。
- 中途反贼削主公时可以放一放，不要把主公保得太健康；否则反贼死光、游戏还没结束，主公立刻知道你是内奸，而且满血主公单挑很难打。
- 主公信你是忠臣时，后期还可以打主公；不信你时，打死忠臣很难，打死主公又直接输，这时平衡局势最好。两边都会想拉拢你，但也可能两边都想干掉你。
- 被识破：跳忠硬撑，或转向帮弱势一方。
- 话术：跳忠；假装是反贼来拉拢；暗示别人是内奸。信息差很难搞。

### 主公

- 开局：不出手先发育；压威胁大的武将；用锦囊试探。身份都不明时锦囊不好针对，常开群攻（南蛮、万箭）。
- 认忠臣：谁打了打我的人；谁救我或给我牌；谁从没打过我。口头跳忠不算数。
- 可疑跳忠者：当内奸先利用；嘴上信任暗中提防；有时甚至和反贼合作先干掉内奸。
- 话术：号召集火某人；假装有闪有桃；拉拢内奸；求救示弱（用户没用过，可作为可选思路）。

### 通用

- 听到别人报手牌：看他的身份立场，再对照手牌数和之前出过的牌，对不上就是在吹。
- 口头跳忠几乎不提供信息（"正式打牌时全场都在喊自己是忠臣"），有信息量的是行动。
- 说谎底线：不歪曲公开事实，不冒充系统或规则。
