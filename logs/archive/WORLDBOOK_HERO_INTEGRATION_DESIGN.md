# 世界书、武将数据与全局设置接入设计

> 日期：2026-08-03
> 原则：游戏引擎是唯一规则来源。世界书只帮助AI理解，不直接修改规则状态。

## 1. 当前数据分层

### 1.1 运行时真相源
- `data/heroes.json`：游戏选将、Player.hero、前端详情的运行时武将数据。
- 当前数量：5将。

### 1.2 世界书源数据
- `worldbook_generated/heroes/heroes_27_complete.json`：27将、54技能的描述与AI策略。
- `worldbook_generated/cards/*.json`：88张卡牌的世界书数据。
- `worldbook_generated/rules/*.json`：阶段、模式、伤害规则。

### 1.3 规则代码
- `game_engine/skills_generated.py`：44个生成类，但多数仍是TODO框架。
- `game_engine/event_bus.py` / `skill_system.py` / `rules_engine.py`：最终决定技能是否触发、目标是否合法、效果如何执行。

## 2. 27将导入流程

### 阶段A：转换与校验
1. 读取 `heroes_27_complete.json`。
2. 统一为运行时字段：
   - id/name/faction/max_hp/image
   - skills[].name/type/trigger_event/description/worldbook
3. 检查：
   - 恰好27个唯一武将ID；
   - 技能总数54；
   - 所有技能名和 `SKILL_REGISTRY` 映射；
   - 势力、体力、技能数组字段合法；
   - 图片缺失只报警，不阻止数据导入。
4. 备份旧 `data/heroes.json`。
5. 原子写入新文件，避免写一半导致服务器读取损坏。

### 阶段B：运行时使用
- 大厅/选将页从 `/data/heroes.json` 读取27将。
- 开局配置只提交选中的完整hero或hero_id。
- 服务器以hero_id重新从运行时数据中解析，防止客户端伪造体力和技能。
- PlayerState保存运行时hero快照。
- 游戏界面头像详情窗口展示技能描述和世界书摘要。

### 阶段C：技能上线状态
每个技能增加 `implementation_status`：
- `data_only`：仅展示和AI理解，不可发动；
- `partial`：部分机制可用，UI标记实验性；
- `active`：规则、交互和测试通过，正式可用。

只有 `active` 技能才进入引擎 `available_actions` 或事件监听器，避免“按钮可点但没有效果”。

## 3. 世界书运行时注入

### 3.1 决策Prompt
每次AI决策按以下顺序组装：
1. 固定系统原则：只能选择引擎合法操作。
2. AI自己的身份和武将技能。
3. 当前阶段规则。
4. 场上武将的公开技能摘要。
5. 手牌相关卡牌条目。
6. 用户自定义世界书命中条目。
7. 当前公开局势和合法操作列表。

### 3.2 检索条件
- 常驻：用户标记constant的条目。
- 武将命中：当前在场hero_id、武将名、技能名。
- 阶段命中：prepare/judge/draw/play/discard/end。
- 卡牌命中：AI手牌和合法操作中的卡名。
- 事件命中：受伤、响应、判定、濒死等。

### 3.3 预算
- 总世界书预算默认4K token。
- 优先级：自身技能 > 当前阶段 > 当前卡牌 > 在场其他技能 > 自定义非命中条目。
- 超预算时按优先级截断。
- 自定义条目单局配置传入，不允许它直接修改规则状态。

## 4. 全局设置界面

所有页面加载 `frontend/js/global_settings.js`，右上角提供统一齿轮入口。

当前设置：
- 卡牌动画速度；
- AI思考状态显示；
- 新AI默认Provider/Model/Temperature；
- 内置世界书启用开关；
- 自定义世界书启用开关；
- 运行时武将/源武将/技能类/卡牌数量状态。

完整设置页额外提供：
- 武将JSON前端预检；
- 自定义世界书增删；
- 数据状态说明。

后续统一扩展：
- 音频/BGM；
- 聊天模型独立配置；
- API调用超时和重试；
- 世界书token预算；
- 动画/特效；
- 自动存档和身份卡；
- 语音/TTS。

## 5. AI思考过程展示设计

当前只展示：
- “某AI正在思考”；
- 决策完成；
- 模型返回的简短reasoning摘要。

后续要求：
- 在聊天区域显示简短、可公开的决策摘要，例如“优先攻击低体力目标”；
- 不显示模型隐藏思维链；
- 支持思考开始、流式摘要、思考结束三种消息；
- 思考消息不得阻塞动画ACK和规则结算；
- 全局设置可关闭显示。

## 6. 卡牌动画与引擎同步

协议：
1. 引擎确认操作合法。
2. 服务端发送 `card_to_discard`，附带animation_id。
3. 浏览器播放“来源 → 中央 → 弃牌堆”。
4. 浏览器发送 `card_animation_done`。
5. 服务端收到ACK后继续卡牌效果、响应或AI下一操作。
6. 浏览器断线/后台时2.5秒超时降级，避免对局永久卡死。

响应牌、过河拆桥弃牌、手牌上限弃牌、濒死桃均使用同一协议。

## 7. 测算与验收指标

### 7.1 数据导入
- runtime_hero_count = 27；
- unique_hero_id_count = 27；
- skill_count = 44；
- registry_mapping_rate = 100%；
- 前端选将渲染成功率 = 100%。

### 7.2 世界书
- 每次决策记录命中条目ID；
- 估算输入token；
- 世界书部分≤4K token；
- Prompt构建时间<100ms；
- 无关条目注入率抽样<10%。

### 7.3 技能
- 每技能至少：2个正常案例 + 2个边界案例；
- 54技能单元测试全部通过；
- 事件注册率100%；
- 非法操作率<5%；
- 4种模式每种至少10局自动对局无卡死。

### 7.4 UI与同步
- 每张实际进入弃牌堆的牌都有原因提示；
- 每个card_to_discard都收到ACK或明确超时；
- 正常前台浏览器ACK率目标≥99%；
- 动画未完成时AI不得执行下一张牌。

## 8. 推荐实施顺序

1. 27将数据转换脚本 + 校验测试。
2. 原子替换 `data/heroes.json`，选将页验证。
3. 为技能增加implementation_status。
4. 统一事件名和技能注册接口。
5. 先接入7个机制代表技能，再批量扩展。
6. 记录世界书命中、token和延迟指标。
7. 完成54技能后再开放技能发动按钮中的实际操作。
